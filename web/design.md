# 紫卡工具网页版 · 设计决策

面向「以后要改这个页面的人」。记录**为什么这么做**，不只是做了什么。

## 一、范围与不做的事

| 决定 | 理由 |
|---|---|
| 版块顺序 ① 洗卡模拟器 → ② 计算器 → ③ 倾向/区间表 → ④ 口径与词汇 | 倾向查询是高频操作，排在计算器之后；「词汇表 + 口径说明」都是「看一眼就走」的背景资料，合并成一个附录版块放最后。数据表 / 倾向表 / 参数表 / 融合表 / 参考表的**原始内容一律不展示**（回归探针 `调试/_probe_*.cjs` 有这条断言，防止改样式时误把整张表渲染出来）。③ 是「算出来的区间」，不是原始倾向表 |
| 词汇表与口径说明合成一个「④ 口径与词汇」 | 两者都是「看一眼就走」的背景资料，放在功能后面当附录。`id="gloss"` / `id="mech"` 已删，回归探针 `调试/_probe_*.cjs` 断言它们不能复活 |
| 页脚只留快捷键提示 | 来源行 / 署名等元信息不渲染。`meta` 仍留在 `data.json` 里，只是不渲染 |
| 单文件离线，数据内联在 `window.ZKDATA` | 双击就能开，不需要起服务、不需要联网。代价是 130 KB 一个文件，可接受 |
| 术语统一叫「融合」 | xlsm 全程用「融合」，以源表为准 |
| 保留 xlsm 的评级名（极品S / 牛逼A / … / 垃圾F） | 这些名字来自 xlsm「参数」表，是这张表自己的分档习惯。页面在「口径说明」里明确标注：**这是工具口径，不是官方说法** |

## 二、美术令牌

底色近黑蓝（`#0b0d12` / `#12151d` / `#161a24` / `#1b2030`），卡片大圆角 + 竖向渐变，
强调色只走「8%~20% 透明底 + 同色边框」，hover `translateY(-2px)` / .2s。
版式沿用同类紫卡工具的通行做法，但**主色保留 Warframe 金 `#c9a227`**：

- 金 = 主强调（按钮、标题、倾向、正面汇总）
- 紫 = 只给融合相关（融合按钮、产物、融合词条值）
- 青 = 只做点缀（hover、聚焦、链接、键盘高亮）
- **绿 = 正面词条，红 = 负面词条**
  ⚠ 不用「涨红跌绿」的行情口径 —— 这里是游戏词条的正负。
  这是一对**全局**变量（`--pos*` / `--neg*`），洗卡区的 +/− 徽标、评级徽标、
  ③ 区两张表的表头与数值列全走它，改一处就全页统一翻转，不要只改 ③ 区。

不做全屏 Hero——工具页要省空间，用左对齐标题条 + 首屏模块入口。

### 开头与导航

- `h1` **左对齐纯色**（`color:var(--strong)`，不用 `background-clip:text`）——
  渐变文字在亮色主题下会漂移成灰，纯色最稳。标题 + 徽标 + 两行说明靠左，
  右上角放语言 / 撤销 / 重做 / 主题（控件靠右 `.hd-right`，同一行 `justify-content:space-between`）。
- 标签导航用 `position:sticky` + 金色下划线标当前项，不用 `fixed` ——
  `fixed` 导航一换行就会盖住标题，`sticky` 不存在这个耦合。
- 首屏入口卡（`.entries`）4 张，对应 4 个版块。

`section{scroll-margin-top:58px}` 配合 sticky，点标签跳过去时版块标题不会被压在标签条底下
（无头 Chrome 探针会量「版块标题 top ≥ 标签条高」）。
导航高亮由 `initNavSpy()` 做：**取最后一个已经滚过判定线的版块**，不是「离顶部最近的那个」——
后者在短版块上会来回跳。

### 换肤（明暗）时的约束

1. 所有颜色都是 `:root` 上的 CSS 变量；亮色只在 `html[data-theme=light]` 里**覆盖变量**，不重写规则。
2. **新样式不许写死颜色**。半透明点缀也要走变量（暗色的 `rgba(201,162,39,.16)` 在亮底上会糊成灰）。
3. 必须同时设 `color-scheme`——它管浏览器自己画的滚动条和 `<select>` 原生下拉面板。
4. 预置脚本必须在 `<style>` 跑，否则刷新闪一下白。
5. app.js 里的内联 `style="color:..."` 也要用 `var(--xxx)`，不能写 `#c9b6fd` 这种字面值。

## 三、手机适配（窄屏）

窄屏下界面会「飞」（元素错位、整页被撑宽）。根因不是某个样式写错，而是**桌面优先的假设**：

| 问题 | 为什么会飞 | 当前做法 |
|---|---|---|
| `table.slots` 五列硬排（词条下拉 130px + 数值 100px + 锁定 + 显示） | 桌面约 590px 才够，手机上每张卡横向溢出 200 多像素，**三个卡面把整页撑宽** | ≤700px **卡片流**：表头整行收起，每条词条变成一张卡（`tr{display:flex;flex-wrap:wrap}`），列名由 `td:nth-child(n)::before` 补上 |
| 计算器 `table.res` 9 列 / 等级换算 11 列 | 表格无法折行，宽度是硬需求 | 套 `.tscroll{overflow-x:auto}`，让**表格自己横滚**，不让整页横滚。手机上加一行「表格较宽，可左右滑动查看」的提示（`.tswipe`，桌面端 `display:none`） |
| 控件写死 `min-width`（搜索框 230/240px、下拉 130px） | 写死的宽度不会随屏幕缩，直接顶破卡片 | 一律删掉，宽度交给 CSS 的 `.kv input`（`flex:1 1 220px;min-width:0`）。宽表内部的 `min-width:150px` 可以留 —— 它在 `.tscroll` 里跟着表格滚 |
| 顶部导航 | `sticky`（见上一节）。窄屏仍需**保持单行**：链接横滑 + `mask` 右缘渐隐 | ≤400px 收字号与内边距；`.hd-right` / `.hd-tools` 允许换行（320px 上「语言 + 撤销 + 重做 + 主题」一排会顶出 29px） |
| 导航里横滑的链接 | 右缘被硬切，类似 bug | `mask-image:linear-gradient(90deg,#000 calc(100% - 16px),transparent)`，用 mask 而不是盖一层渐变 —— 不挡点击 |
| 首屏 4 个入口卡 | 压成 1 列会铺满整整一屏，要滑很久才看到 ① 洗卡 | 手机上保持 **2 列**（`minmax(140px,1fr)`）。这是刻意不缩的：一列更「安全」但更难用 |
| ③ 区右侧两张表 | 桌面上是 1fr 1fr 并排 | ≤760px 变单列；`.r-scroll` 去掉 `max-height`，不要套一层纵向滚动；表头 `position:static`（容器不滚了，sticky 会粘到整页顶部被导航盖住） |
| ③ 区第三张（融合表）限高 420px | 陷阱：`.r-tbl.fuse .r-scroll` 特异度比手机块里的 `.r-scroll{max-height:none}` 高 | 限高写进 `@media(min-width:701px)`，不要不带媒体查询地写——**媒体查询不加特异度**，写歪了手机上又会冒出一层内嵌滚动 |

### ★ 怎么验证（排版只能用真渲染验）

jsdom 没有排版引擎，`getBoundingClientRect()` 全是 0 —— 手机上飞没飞它测不出来，因此 **`domtest.js`（jsdom）已退役**。
现网排版 / 行为验收统一走 `调试/` 下的无头 Chrome 探针套件：`cdp.cjs`（Node 22 自带 WebSocket 直连 CDP 的工具层）+ `_probe_*.cjs`（各功能探针）、`chk_disp.cjs`、`lang_e2e*.cjs`、`wash_n_e2e.cjs`、`ocr_e2e.cjs`，真渲染后做 DOM / 排版 / 行为断言：

```bash
node debug/_probe_smoke.cjs            # 六路由 display 断言
node debug/_probe_price.cjs            # 功能6 价值表 31 条断言（动态基准）
node debug/fetch/mobile_shot.py 390 1500 out.png dark   # 截图（可选第 5 个参数：先隐藏某些版块，让目标顶到最上面）
```

**★ Chrome 无头在 Windows 上有最小窗口宽度 ~500px** —— 直接 `--window-size=390` 量到的 `innerWidth` 是 500，
等于根本没测到手机宽度（截图看着「右半边被切」时，实际是 500px 布局被裁到 390，并不是真的窄屏溢出）。
探针因此把页面塞进**定宽 iframe**：iframe 里的媒体查询按 iframe 宽度算，才是真的手机视口。
`--allow-file-access-from-files` 是为了让父页把 iframe 里的探针结果抄出来。

## 四、数值口径（和 xlsm 的对齐点）

- 数值 = 基准值 × 组合系数 × 倾向 × 浮动(0.9~1.1)。
- **★ 融合产物也乘组合系数**。
  融合只换了词条，数值仍然是按同一套公式重新随机出来的，没有理由少乘一个系数。
  ⚠ **xlsm 的 `融合()` 不含 `coef`**（`s7.vba`：普通重滚 `base*coef*disp*vol`，
  融合产物 `base*disp*vol`）—— 网页版按含 coef 的口径实现，不照搬该处。
  实现见 `doFusion()`：`b * card.combo.gain * w.disp * vol`（产物固定落正面槽，取 gain）。
  回归探针 / 构建期 `构建/_audit_js.py` 会断言「不乘组合系数」这句话在页面和代码里都不能再出现。
- 理论值 = 基准 × 系数 × 浮动 × 倾向 / 9 × (1+等级)；**负面槽的 min/max 对调**。
- 对中差值：正面 `C/E-1`，负面 `1-C/E`。
- 规则全部按**数据表行号**判定，绝不按名字（译名会变，行号不会）：
  永正 = 融合 35~52 全类别无条件 True，近战另加 `{2,3,9,10,11,12,27,29}`、非近战 `{9,10,11,12,20}`；
  永负 = 只有 30；永不正 = 近战 + 35~52。
- **空基准值（null）≠ 0**：这类武器根本没有这条属性。JS 里 `isFinite(null) === true`，
  所以 `baseOf()` 必须显式返回 NaN，否则会洗出 `+0.00%`、融合产出 0 值。
  判据：按「有基准值」过滤后近战正面池正好 **37 条（含融合 14）**，与 xlsm 计算器 N5 缓存一致。
- 计算器**必须包含融合词条 35~52**（计算器检验的是最终成果）。
  唯一过滤是「负面槽不得出现永正项」，正面三格额外排除永负(30)。
- **派系伤害的基准值 1.45 是倍率不是百分数**：它等于 +45%，③ 区按 `×1.45` 显示。
  （xlsm 里「洗出来只有 +1.x%」的疑问由此澄清：那不是 +1.45%，是 ×1.45。）
  实现上先 `(基准−1)×100` 还原成百分数再算区间，最后再折回倍率显示。

### ③ 倾向 / 区间表的口径

- 版面：左栏选武器 + 正面数/负面/等级，右栏**三张表** ——
  上排正面（绿）+ 负面（红）并排，下面**整宽**一张融合专属词条（紫）。
- 数值 **不用 `×1.5 ×10 ×0.66 …` 那套写法**，直接用本表自己的组合系数：
  `基准值 × 组合系数 × 浮动 × 倾向 × (等级+1) ÷ 9`。两者**代数等价**：
  `1.5 × 10 × 0.66 × 9 ÷ 9000 × 100 = 0.99`，正好是本表 2正0负 的 gain。
- 「基准分数」口径 = 本表基准值 **÷ 9000**（穿透/范围/初始连击/连击持续时间 是 **÷ 90**）。
  ⚠ 「÷150」是错的，正确值是 ÷9000。
- 交叉验证：5 类别 × 正负面 × 5 档倾向 × 4 种组合 × 3 个等级 = 21240 个数逐项比对，差异全部 ≤ 1%，
  来源两处：① 参照常量被截成 float32（0.013333 而非 0.0133333）；
  ② 「触发时间」霰弹 / 近战本表取 99.0、参照值 99.99（差 1%，疑为本表录入取整）。
- 正面 / 负面两张表只列**可洗出的 2~34 行**（`RG_FROM..RG_TO = ROLL_FROM..ROLL_TO`）。
- ★ **融合专属词条（35~52）单独一张表**：
  它们**洗不出来**、只能靠融合换到，所以不能混进「洗卡区间」那两张表；
  但数值走的是**同一套公式**，只是产物固定落正面槽 → 系数取 `gain` 那一档。
  实现：`rgRowsFuse()` —— 循环 `FUSE_FROM..FUSE_TO`，`rgRange(..., isPos=true)`，
  基准值为空的行（这类武器出不了这条融合属性）直接跳过。近战 45~48 就是这种情况。
  ⚠ 表的外观走 `--fuseFg/--fuseBg`（全站「融合」统一的紫），和正面绿区分开。
- 页面上**不渲染**一致性核对表。
  `RG_REFVAL` 常量**必须留着**：回归探针 `调试/_probe_*.cjs` 拿它做静态自检，防止口径被改回
  「÷150 / ×1.5×10×0.66」。配套断言「`#rgSpot` 不存在」。

## 五、融合提示体系（玩家记不住配方）

玩家通常记不住什么能融合，工具得自己把答案递到手上 —— 融合这块**不能只是两个空下拉**：

| 做法 | 说明 |
|---|---|
| 材料下拉只列「有可用配方」的词条 | 过滤条件 `fusePartners(cat, row).length`，且**排除 35~52**（融合词条只能当产物）。无条件列卡面 4 条时，玩家自己挑中一对的概率很低 |
| 下拉里的搭档**必须是卡面上的** | 按 `onCard` 过滤（选了以后 `doFusion` 找不到第二个材料 →「所选词条已经不在当前卡面上了」）；没有搭档时明说该去洗哪一条 |
| 选了一个材料 → 列出卡面搭档 chip | 每个 chip 直接写 `A → 产物`，点一下**两个下拉都填好**（`data-a="fusefill"`），不用再自己配对 |
| 实时提示条 `.fusehint` | 两个都选了 → `✓ A ＋ B → 融合出 X，数值按「基准 × 组合系数 × 倾向 × 浮动」得到一个固定值`（浮动继承两条材料里较高的那个，由 `volOf()` 反解，不重新随机）；卡上已有融合词条 → 红色提示（每卡最多 1 条） |
| 折叠的「融合配方速查」`.fuseref` | 完整配方表，按当前武器类别裁剪（产物没基准值的配方不列），卡面上已有的材料那行高亮 |
| 选了 A 之后如果和已选的 B 配不上 | 直接把 B 清掉，不留下一个必然失败的半截状态 |

配对判定一律走 `FUSE_MAP["小行号,大行号"]`（配方无序），产物行号由 `fuseProd()` 查。

## 六、撤销栈的口径

进栈：选词条、改数值、切锁定、选融合材料、开卡、洗卡、融合、复制到计算器。
不进栈：换语言（它不改数据）。

快照存武器**下标**而不是对象——存对象恢复出来是副本，`K.w === w` 不成立，
候选列表的「已选中」高亮就废了。深度 80。

快捷键让位规则：焦点在文本框里时 `Ctrl+Z` 交还浏览器（此时要撤销的是刚敲进去的字符）。

## 七、数据来源与可信度

`data.json` 里的 `meta`（source / verifiedAt / exportedAt / confidence / counts / rows）
全部由 `构建/export.py` 从 xlsm **派生**（源文件 mtime、各表行数），不手写——手写一定会和表脱节。
（**不在页脚渲染**，只留在 data.json 里给以后排查用。）

改了 xlsm 的数据后：`python build/export.py && python build/build.py <带日期的产物名>` 重来一遍，再跑 `调试/_probe_*.cjs` 无头 Chrome 探针套件（构建末尾会自动跑 `构建/_audit_js.py` 做 JS 卫生闸门：空 catch / for…in 守卫 / innerHTML 唯一出口）。
