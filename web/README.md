# Warframe 紫卡模拟器 · 网页版

一个**完全离线、单文件**的网页工具，用于 Warframe（星际战甲）紫卡（Riven Mod）的：

- 倾向数值查询与词条区间对照
- 紫卡数值计算、评级、等级换算
- 开紫卡 / 洗卡 / 融合的概率模拟
- 紫卡收益（DPS）评估
- 截图自动识别（本地 OCR，不上传任何数据）
- 紫卡市场成交价参考

无需联网、无外部依赖、无后端。交付物是 `产物/` 下的单个 HTML 文件，可直接发给任何人，也能单独分发。

---

## 功能一览

| 分区 | 用途 |
|------|------|
| **倾向数值区间表** `#ranges` | 每把武器的紫卡倾向值与各词条数值区间，按武器类型浏览；武器名可点跳转到对应区间。 |
| **分析识别计算器** `#calc` | 粘贴紫卡截图 → 本地识别武器名、等级、四条词条与数值并自动填入计算器；检验对中差值、评级、等级换算。 |
| **开卡洗卡融合模拟器** `#open` | 随机开紫卡、自选武器继续洗卡、融合；附带洗卡次数与辣椒（Kuva）总消耗统计，以及「洗卡前 / 当前」双卡对比。 |
| **紫卡收益计算器** `#dmg` | 选武器 → 选配卡模板 → 填紫卡词条，给出相对「不带这张卡」的 DPS 收益、每条词条的边际贡献与社区分档。 |
| **洗卡左右建议器** `#choose` | 左右两张候选紫卡各截一张图分别识别，用同一套收益引擎现场计算，辅助判断该保留哪一张。 |
| **紫卡价值表** `#price` | 每把武器紫卡的成交价快照：中位价、均价、未洗 / 已洗价格、最高单笔、流动性与近 8 周变动。另含单词条热度与词条组合价格排名。 |
| **口径与词汇** `#about` | 数值怎么算、哪些词条不会出现、名词含义。 |

其它特性：

- **三语言界面**：国服 / 国际服 / English，武器名与数据名跟随切换。
- **暗 / 亮双主题**。
- **完全离线**：OCR 引擎（onnxruntime-web）与识别模型全部内嵌在 HTML 中，识别过程不发任何网络请求。
- **移动端适配**：窄屏下各功能区自适应排版。

## 怎么使用

### 直接用

用任意现代浏览器打开：

```
产物/20261031紫卡模拟器V10.html
```

自包含单文件（JS / CSS / OCR 模型全部内联），不需要安装任何东西，断网也能用。
倾向口径内置「现行版（全库统一 1.2）/ 倾向版（每把武器按自己的倾向）」切换，在目录底部「倾向口径」一行点选。

### 从源码重新构建

需要 **Python 3** 与 **Node.js 22**（仅用于构建期校验，运行时不需要 Node）。

```bash
cd web

# 1) 清注释（新增源文件要先登记到 构建/squeeze_src.py 的 BUILD_FILES）
python 构建/squeeze_src.py --apply

# 2) 组装源码 → 中间产物
#    ⚠ OCR_VER=v6 必须带上！build.py 的默认是 v3，而交付件用的是 v6 模型
#      （ppocr_keys_v6.txt 行数不同）。不带会得到识别更慢、丢词条的「假新版」。
OCR_VER=v6 GZ_MODELS=1 python 构建/build.py 产物/20261031紫卡模拟器V10.html

# 3) 内嵌 OCR 运行时并去掉注释 → 最终交付件
python 构建/embed-ort.py --src 产物/20261031紫卡模拟器V10.html \
                          --out 产物/20261031紫卡模拟器V10.html --strip
```

> `build.py` 不带路径参数时默认写 `dist/riven-sim-web.html`（英文名分发版）。
> 第 2 步产物是**未嵌 OCR 运行时的中间态**，必须接第 3 步。

> `embed-ort.py` 内嵌的 ONNX 运行时优先读取本地的 `运行时/ort/`；该目录已从仓库省略（约 14 MB 的二进制缓存），重建时加 `--force-download` 即可从 CDN 拉取（需联网）。交付的 `产物/*.html` 本身已内嵌 ONNX，断网也能用。

> 数据源（`源码/数据/zkdata.js` 等）通常无需改动；仅在武器库或价值表更新时才需要重跑数据导出脚本（`构建/export.py`）。

### 回归

`调试/` 下是一套基于无头 Chrome（CDP）的探针，Node 22 自带 WebSocket，无第三方依赖：

```bash

node 调试/run_all.cjs --only=price,combo

node 调试/_probe_price.cjs            # 价值表

node 调试/_probe_numcheck.cjs 产物/20261031紫卡模拟器V10.html 测试/卡图/c2.png
node 调试/_probe_zrows.cjs    产物/20261031紫卡模拟器V10.html 测试/卡图/c4.png

# 挂单侧（改 wm-fill-core.js 后跑）
node 调试/_probe_fill.cjs             # 只看断言；--verbose 连日志一起打
```

`测试/卡图/` 里是一组真卡截图（正常卡、小图、模糊、极限压缩 JPEG、双卡并排、两行名、
低清、词条贴底、拉丁名截断等），供探针按需取用。

## 实现原理

各功能都跑在同一份内联脚本里（构建时把 `源码/` 拼成单文件），下面按分区说明数据与算法来源。

### 倾向数值区间表
- 数据源是 `源码/数据/zkdata.js`：每把武器带 `disp`（倾向）与各词条的基准值/区间。
- `源码/框架/weptable.js` 按武器类型（步枪 / 霰弹 / 手枪 / 曲翼 / 近战）分组渲染每把武器的词条区间。
- 物理词条（冲击 / 穿刺 / 切割）按「该类型在武器伤害里的占比 ≤ 25% 则不出现」的规则灰显划掉；占比遍历本体与每个技能形态取最大值判定。后坐力等方向性字段统一在 `ZKC.disp()` 与引擎里取方向，不在多处各写一套。

### 分析识别计算器
- **预处理**（`源码/识别/preprocess.js`）：紫框检测 → 凸包 + 最小外接矩形旋正 → 贴 632×800 模板 → 亮度/对比度自适应 → 去孤立碎块 → 多尺度缩放。这一层只认图片、不绑引擎。`fitToTemplate` 的返回里带 `ar`（宽高比），给卡形护栏用。
- **极性识别**（`源码/识别/polar.js`）：在固定 ROI 切出极性图标，字形掩膜 + 模板匹配（bbox 拉伸 IoU）判 Naramon / Vazarin / Madurai。
- **文字识别**（`源码/识别/ocr_onnx.js`）：检测 + 识别两个 ONNX 模型，经 onnxruntime-web 在浏览器内推理；模型 gzip 压缩后分块 base64 内嵌，页面空闲时才解码，不阻塞首屏。
- **分区**（`zonesFromText()`）：用「行高明显最大的一行或两行」定出**名字块**，只把**词条带起点**下移到它下面；名字分区**只许往上放大**（收窄会切掉两行名的第二行），另有名字块**向上补行**（紧贴块顶、字高 ≥ 块高 0.8 的行补进来，最多 2 轮）。切不动就退回固定分区。诊断字段 `window.__zones` / `__zoneSplit` / `__zoneDbg`。
- **武器模糊匹配**（`rankWeapon`）：中文走 `simScore` + 混淆表 + 拼音，英文列 `simScore(row.en) - 5`。两个硬约束：① `latinIsRivenName()` —— 卡面拉丁串若整串能由词根拼出 ≥80% 且命中 ≥4 字符，判为**紫卡名**，不参与武器英文比对；② `nameLocked` —— 中文/英文名 `score >= 92` 时不再做同族扩展（否则「执法者」会被推向「圣洁执法者」）。
- **容量与倾向上限**：卡面右上容量是硬约束，`rankCostOf(levelText, rank) === 0` 时只在该等级上搜索。反推用的倾向必须是**这把武器自己的真值**（`ZKC.dispReal(w)` 读 `ZKDATA.dispSnapshot`）——统一 1.2 只服务收益展示与计算。段位行正则 `RANK_LINE_RE` 含繁体/错字变体。
- **名字兜底**：名字分区里只剩「增幅」这类短尾行时，说明两行名的首行没进来，此时把名字区**往上再要一条**重读（先只对已有框的行补 `rec`，一条字都没有时才重跑 det+rec）。判据用结构而不是分数。诊断字段 `window.__nameRetry`。
- **底栏（段位 / 循环）**：底栏那一行常被两个分区各读一遍，跳过所有「也是段位行」的副本再取；英文卡把三样挤在一行时，`parseRolls` 必须先单独找循环关键词（含 `Rerfol` / `Rertol` 这类误读）再退回 `Ranks`。段位另有结构兜底：内容最底 14%、形如「?位 + 一到两位数」就认定。
- **数值复读**（`verifyNumbers()`）：把数字那一小段单独裁出来，按 48 / 64 两个尺度各读一次，**只标记不改写**（`numConflict` → 预览行尾 `⚠`）。
- **卡形护栏**：`ar < 0.25 || ar > 2.0` 判「紫色像素圈住的东西不是一张卡」，改走文本框补救援（`window.__fitWhy` / `__fitAr` 记原因）。`detPrep` 另有长边封顶 2600，避免分区又宽又扁时把张量拉到 2600 万点。
- 识别结果由 `源码/框架/app.js` 的识别接管逻辑填入计算器；计算器按 `WF` 引擎（`源码/引擎/riven-engine.js`）做对中差值、评级、等级换算，并可切换倾向看数值变化。
- `ocr.js` 是 IIFE，别的文件拿不到它的内部函数 —— 需要跨文件调用的统一走 `window.__OCR_API` 桥。
- 识别完成后向 `#ocrWarn` 写逐字段的缺失与低置信汇总（武器未认 / 歧义 / 推断、词条缺失、段位 / 循环 / 等级 / 极性缺失）；识别空白不等于数值为 0。
- **市场行情参考**（`源码/框架/priceref.js` + `源码/数据/zkpricedb.js`）：识别完一张卡，综合评级下面给出「快出手 / 正常挂 / 耐心等」三档价，以及最像的几张在售卡，跟着武器 / 词条 / 数值实时重算。
  - 引擎口径：正词条 Jaccard × 数值接近度（`VAL_MIX 0.45` 混合）+ 负词条一致加成 `0.12`，取「相似度 ≥ max−0.05」那一层当样本，再剔掉超中位 6 倍的钓鱼价。
  - 行情库由抓价脚本生成，**不许手改**；生成后由 `构建/pricedb_slim.py` 做瘦身与换键（`ks` / `gk` / `k` 存 slug，`stats` 只留 `slug → 词条行号`），再由 `构建/pricedb_fixcombos.py` 校验组合榜合法性（紫卡最多 3 正 1 负，超出的组整组删除）。
  - 武器匹配走**家族**：WM 的紫卡是武器家族维度，`cn/intl/en` 找不到时退回本体名 `bcn/bintl/ben`。
  - **双服**：`estimate(weapon, pos, neg, store)`，`store = 'intl'` 用国际服挂单，`'cn'` 用国服在售挂单现算的池。两边结构一样、算法同一套，估价在哪个服就在哪个服的挂单里比；切服会触发 `renderCalc()` 重算。
  - 国服池带 `clamp: true`，三档价一律截到 300（词条数折算会把价格顶出上限），前端 `capv()` 与生成侧同值；国服没有这把武器的挂单时返回 `noPool`，面板直说，不拿国际服数字充数。
  - 参考价分支：放宽池里词条更多的挂单按「每多一条正面 ×0.75」折算，负词条按严重度四档（1.00 / 0.85 / 0.70 / 0.50）折价。
  - `p50 >= cap × 0.99` 时三档价会挤在一起，面板单独提示「已顶到价格上限」。
  - 派系词条（`damage_vs_*` / `damage_to_*`）存的是**倍率**，`isMultStat()` 认出来后渲染加 `×`，否则 1.06 会被读成 1%。
- **词条名只写键**：引擎、面板、OCR 缩写表都不写中文名，键查 `源码/数据/names.json` 的 `statKeys`（`ZN(k)` / `SE(k)` / `ZKC.statMap('short'|'en')`）。

### WM 挂单填表
- 载荷进来先过 `checkPayload()`：武器、正 1–3 条、负 ≤1 条、总数 ≤4、数值有限且非 0、范围（倍率 ±4 / 百分比 ±400）、同名重复、同一行重复。任何一条不成立就**一个字都不往页面上写** —— 错一条都是「看起来成功」的错单。
- 词条全部进表后 `nameOracle()` 读 WM 自己生成的卡名候选：1 个 = 组合被 WM 认可，多个 = 有歧义，0 个 = WM 没认。**只读不代填**，写它等于绕过这层整卡校验。
- `pruneStatRows()` 只删「彻底为空」的尾部行（最多 3 轮，行数没减少立即停）；找不到删除按钮会明说「请手动删掉再提交」，不静默返回。

### 开卡洗卡融合模拟器
- 开卡池是 `ZKOPENABLE`（本体 + 变体·无本体，排除开不出卡的变体·有本体）。
- `genStats` 按武器类型套「永正 / 永负 / 物理占比 25% / 派系」闸门，为每张卡随机抽 2~3 条正面 + 1 条负面词条并赋随机值。
- 洗卡在已选武器上重复掷词条（锁定词条原样保留、组合类型冻结）；`openNRun` 支持批量 N 次模拟，统计词条分布与辣椒总消耗。
- 融合把两张同武器卡按融合词条规则叠加；产物浮动继承材料里较高的那个，不重新随机。

### 紫卡收益计算器
- 选武器后 `源码/引擎/riven-router.js` 按武器名解析流派（远程 / 近战），结合 `源码/引擎/weapon-db.js` 的基础面板给出配卡模板。
- 填紫卡词条后，`WF` 引擎（含护甲减伤封顶、派系克制倍率、元素组合）算相对「不带这张卡」的 DPS 增量；近战给范围与连击、枪械给弹匣与穿透，面板分开算。
- 额外给出每条词条的留一法边际贡献与社区分档（与词条推荐面板同源）。

### 洗卡左右建议器
- 左 A、右 B 各截一张图，分别走同一套识别链路（先 A 后 B）；同一把武器的名字与等级只填一份，每边 4 条词条可下拉改、数值可改，图像漏行可「粘贴文字」按行补齐。
- 两个卡面板、结论与报告都用同一套 `WF` 收益引擎现场计算，改任意一格立即重算。

### 紫卡价值表
- 数据源是 `源码/数据/zkprice.js`（`window.ZKPRICE`）：每把武器一行，含中位价、均价、未洗 / 已洗价格、最高单笔、流动性（样本量）、可靠度、近 8 周变动。
- `源码/框架/pricetable.js` 只列开得出紫卡的武器（`ZKOPENABLE`），武器名跟随界面语言，价格列可自行勾选隐藏，默认只列有成交（流动性 > 0 且中位价有限）；勾上「含无成交武器」看全量；支持搜索、筛选与排序。
- 武器表下面两张分析表共用 `源码/数据/zkpricedb.js`（`window.ZKPRICEDB`）的 `combos` / `single` / `opt`，三者都是 `{intl, cn}` 双 store：随「国际服 / 国服」按钮与界面语言换数据源（`ZKSTORE`），当前服没有数据时退回另一服并在统计行标注。
  - **单词条热度**：正 / 负面两页签，出现率、贵组 / 便宜组、提升、溢价、中位价、样本、集中在。
  - **词条组合价格排名**：按五类聚合「正词条组合 + 负词条」，每类前 60 组。
- 榜单统一剔除占位 / 钓鱼挂单（词条绝对值合计 <20%），参考价定价口径不受影响。
- 国服价格相关列按**同武器内价格分位**折算（国服 300 白金封顶，绝对值不可比），统计行会注明。

## 模块结构

```
web/
├── 源码/
│   ├── 公共/        # 全站铁规则常量（window.RULES）+ 公共函数（esc/safeParse、倾向计算、名称匹配）
│   ├── 数据/        # 武器库（zkdata.js，637 把含形态字段）/ 价值表 / 行情库 / names.json
│   ├── 引擎/        # 收益引擎、武器基础面板、武器名→流派路由、Zaw/组合枪组装数据
│   ├── 框架/        # 页面主逻辑（app.js）、模板、样式、收益计算器与价值表面板
│   ├── 识别/        # 离线 OCR：预处理、极性识别、ONNX 推理、结果解析、模型
│   ├── 资源/        # 卡面底图等静态资源
│   └── 填表/        # 紫卡交易站点（WM）填表引擎与词库源文件
├── 构建/            # 组装 / 内嵌 OCR 运行时 / 清注释 / 命名表校验 / 行情库瘦身
├── 产物/            # 交付的 HTML（可直接分发）
├── dist/            # 英文名分发版（build.py 默认输出）
├── 调试/            # 无头 Chrome 探针（不随交付件分发）
├── 测试/            # 填表测试件（wm-sim.js + wm-sim-bare.html）与卡图
└── 运行时/          # ONNX 运行时素材（_ort_cache），构建期读取，不随交付件分发
```

### 关键约定
- **单一真源**：所有功能以 `源码/` 为准，`产物/*.html` 只是构建结果。改功能请改源码后重新构建，不要直接手改产物。
- **名字单一真源**：`源码/数据/names.json`。改译名只改它，再跑 `构建/gen_names.py --apply` 覆盖 `zkdata.js`。
- **`var` 形态字段**：武器分 `本体`（可开卡）、`变体·有本体`（开不出卡，吃本体紫卡）、`变体·无本体`（可开卡，本体不在库）三种，开卡池 = 本体 + 变体·无本体。
- **数值口径**：收益与区间计算以游戏数据表为准；派系 1.45 是倍率、后坐力方向相反，都在 `RULES` 与引擎里统一处理。
