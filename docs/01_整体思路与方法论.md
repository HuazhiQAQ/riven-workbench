# 01 整体思路与方法论

这张表的改动流程沉淀为下面这套方法。

---

## 一、核心认知：这张表有两种"真相"

这是最基础的一条，其它坑大都从这里派生。

| | 内存里的值 | 文件里的值 |
|---|---|---|
| 怎么读 | COM：`ws.Range('A1').Value` | 拆 zip 读 `xl/worksheets/sheetN.xml` 的 `<v>` |
| 什么时候更新 | 宏一跑就变 | **只在 WPS 保存时**才写回 |
| 最终显示的是哪个 | —— | **文件里的缓存** |

WPS 打开文件时**不一定重算** `FILTER` / `ANCHORARRAY` 这类动态数组，
它直接显示 XML 里存的那份缓存。

> ### 典型案例
> 现象：计算器负面下拉里仍有「额外连击数几率」。查下来 COM 读出来是对的，
> 公式也已改对 —— 但打开文件看到的还是错的。
> 根因：`run_in_wps.py` 的 `Wps` 用 `with` 时 `__exit__` 是 `close(False)`，**从来不保存**。
> 那个文件没有经过 WPS 重算，缓存里的值不会跟着公式更新。
>
> **判据：COM 读出来对 ≠ 文件里对。验收必须离线拆 zip。**

所以 `chk_cache.py` 是这套流程里最关键的脚本之一。

## 二、改 VBA 的三段式（不打开 Excel 也能改宏）

`.xlsm` 里的 VBA 是 OLE 复合文档里的 `vbaProject.bin`，
里面有**压缩过的源码流** + **编译过的 p-code**。

```
dump_raw.py  →  原始字节源码（cp936）
     ↓  decode('cp936') → 存成 UTF-8
   改源码（patch_*.py，用 assert 校验替换处数）
     ↓
inject.py 原.xlsm Sheet7 新源码.vba 输出.xlsm
     ↓
真机跑一次确认行为生效
```

### 三条约束

1. **源码文件必须是 UTF-8**，但**内容要能被 cp936 无损表示**
   （`inject.py` 默认按 cp936 写回；写成 UTF-8 字节 → VBA 按 GBK 读成乱码 →
   **整个模块编译失败 → 工作簿里所有宏一律报「发生意外」**，连没改的宏也挂）
2. **每次动手前重新 dump 取当前磁盘文件**
   文件可能被 WPS 另存过，大小与内容都会漂；拿备份当基底会丢掉这期间的改动。
3. **替换用 `assert t.count(old) == 1`**
   宁可脚本报错，也不要静默改错地方或改 0 处。

## 三、改公式：必须离线改 XML

计算器那 4 格（N5/O5/P5/Q5）是**动态数组**：

```xml
<c r="P5" cm="1" t="array" ref="P5:P21">
  <f>_xlfn._xlws.FILTER(...)</f>
  <v>...</v>
</c>
```

**用 COM 写会退化成只出 1 项**（动态数组属性丢了）。
必须离线改 XML，而且**必须保留 `cm="1"` 和 `t="array" ref="..."`**。

同理，参考·理论区间那 4 个区块若缺 `cm="1"`，就是旧式 CSE 数组、
溢出 ref 冻结 —— 插行后尾部词条会掉队（「格挡角度 / 震地伤害」两行的消失即该机制的表现）。

## 四、验收：必须走按钮路径 + 抽样统计

### 为什么不能 `app.Run`

`app.Run('Sheet7.宏名')` 有两个毛病：
- **静默吞错** —— 宏里 `On Error GoTo EH` 弹的框你看不到
- 宏里有 `MsgBox` 会**永久阻塞**

`run_in_wps.py` 起后台线程轮询 `#32770` 弹窗，读出正文后 `WM_CLOSE`，
并提供 `s.click('CommandButton3')` 走**真实操作路径**。

### 抽样前先确认宏"真的跑了"

宏里到处是这种守卫：

```vb
If 前置条件没满足 Then
    MsgBox "请先……"
    Exit Sub          ' ← 静默退出
End If
```

一旦没满足，**卡片根本没重滚**，你抽 200 次会得到 200 个一样的结果。

> 实例：5×60 抽样得到 `{'连击持续时间': 60}`（60 次全同）——
> 搜索词没命中武器表，宏弹窗后直接退出，卡片没有重滚。

**约束：抽样循环前先读一个「宏写出来的展示格」判空，空就跳过这一组。**

### 对照实验

有效的证据是「同一套用例在缺陷实现上失败、在当前实现上成功」。
`mkscript.py` 干这个：同一份测试脚本，只换输入文件，生成两个版本。

该方法的实测结果：
- 缺陷实现：格挡角度 ✗ 震地伤害 ✗（其余 8 条 ✓）
- 当前实现：10/10 全 ✓

## 五、工作循环

```
接到现象
   ↓
先判断：是「数据问题」还是「代码问题」还是「缓存没刷新」？
   ↓                    ↓                    ↓
改数据表/倾向表      改 VBA / 改公式        s.close(True) 重存
   ↓                    ↓                    ↓
   └──────── 同步传播（见 02）──────────────┘
                       ↓
              真机验证（走按钮 + 抽样）
                       ↓
              离线验缓存 → 部署 → 备份留档
```

## 六、几个反复用到的判断技巧

| 场景 | 技巧 |
|---|---|
| 分不清是 XML 坏了还是 VBA 坏了 | 看报错时机：**Open 阶段就报** → XML/包结构；**Open 正常、只有宏报** → VBA 编码/编译 |
| 找不到某段逻辑在哪 | 往被测模块**追加**一个临时 `Sub`（`inject.py` 是整模块替换，追加即可），一次探一片 |
| 怀疑某个数字是写死的 | 跑 `scan_hardcode.py`，扫 `For x = 2 To N` / `Cells(N,` / 行号比较 |
| 想确认文件里到底是什么 | 拆 zip 直接读 XML，别信 COM |
| 改样式 | **别离线追样式号**（WPS 会重排 `cellXfs`，`count` 属性还会和实际条目数不一致）。用 COM 直接设外观最省事 |
