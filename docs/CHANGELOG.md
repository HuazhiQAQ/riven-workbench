## 一、数值口径

### 1.1 读数上限与倾向上限

| 常量 | 值 | 定义处 |
|---|---|---|
| `VALUE_MAX` | 404 | `源码/公共/_rules.js` |
| `DISP_MAX` | 1.2 | 同上 |
| `DISP_UNIFIED` | 1.2 | 同上 |

- `VALUE_MAX` 推导：`247.5 × 1.2375 × DISP_MAX × 1.1`。读数大于上限时依次 ÷10、÷100。
- 倾向统一后全库武器的当前倾向一律为 1.2，`ZKDATA.weapons` 的倾向分布为 `{"1.2":637}`。
- 页内「倾向口径」切到倾向版时 `DISP_UNIFIED` 写为 `null`，各武器读自己的 `w.disp`（见 2.4）。
- 倾向的唯一出口是 `ZKC.disp(w)`：主态一律返回统一值；倾向态读 `w.disp`。引擎库（`WEAPON_DB`）的武器记录
  只有名字、没有 `disp` 字段，所以 `ZKC.disp` 会按英 / 国际服 / 国服名回查 `ZKDATA` 记录再取；
  组装台合成出来的武器匹配不到就用统一默认值。
- 引擎里 `profile(w).disp` 与 `statCap(w, …)` 必须传 `w`；写 `ZKC.disp()` 无参调用时倾向态只会拿到默认
  1.2，满值 / 浮动 / 区间表就都不跟倾向变了。
- 满值 = `基准值 × 倾向 × 结构系数 × 1.10`，**浮动 = 输入值 ÷ 满值**。满值一变，浮动同时变；
  边际增益只跟输入的绝对数值有关，不随倾向变。

### 1.2 组合系数

词条组合只有四种：**2增益0减益 / 3增益0减益 / 2增益1减益 / 3增益1减益**。

| 组合 | 增益系数 | 负面系数 |
|---|---|---|
| 2+0 | 0.99 | 0 |
| 2+1 | 1.2375 | 0.495 |
| 3+0 | 0.75 | 0 |
| 3+1 | 0.9375 | 0.75 |

- 来源：Excel `参数!B10:B13`（gain，正）/ `参数!C10:C13`（neg，负）。
- 融合产物同样乘组合系数；融合词条（行 35~52）全部为永正。

### 1.3 浮动系数

下限 0.9 / 中值 1 / 上限 1.1。卡面数值 = 基准值 × 组合系数 × 倾向 × 浮动。

融合产物的浮动**不重新随机**，取两个材料里较高的那个
（`doFusion()` 里 `vol = Math.max(volOf(card, m1), volOf(card, m2))`）；
材料自身浮动由 `volOf(card, i)` 反解：`浮动 = 值 / (基准 × 组合系数 × 倾向)`，
第 4 槽（负面槽）取 `card.combo.neg`，其余取 `card.combo.gain`；
反解不出（空槽 / 无基准值 / 倾向为 0）时退 `P.mid` 并夹回 `[P.lo, P.hi]`。

### 1.4 派系词条

- 派系行（16~18 / 42~44）卡面写的是**倍率**：`×0.51` 为减益、`×1.51` 为增益。
- 内部一律按 `(倍率−1)×100` 存百分数（`×0.51` → −49，落负面槽）。
- 输入框按 `toGame()` 显示回倍率（4 位小数 `0.5100`，`×` 只在表格 / 卡面上）。
- 判定一条词条是否减益，除「带负号」外还需「派系倍率 < 1」。
- 词条显示名的唯一出口是 `ZKC.statRowName(row, lang)`（`lang` 0=国服 / 1=国际服 / 2=English），
  从 `ZKDATA.stats` 的三语列取 `cn` / `intl` / `en`；`ZKC.statNameByKey(k, lang)` 也走它。
- 派系这几条两服文案不同：国服「对科普斯的伤害」↔ 国际服「对Corpus的伤害」，英文「Damage vs. Corpus」。
- 价值表按**当前显示的是哪一服数据**取名（`ST.s === 'cn'` → 0，否则 1），English 界面一律英文；
  派生名 `_p` / `_g` / `_nm` 每次渲染现算，切服切语言都不留旧名。

### 1.5 后坐力符号

- 后坐力（行 25）在正面词条是负数、在负面词条是正数 —— 与 Excel 一致，不另立口径。
- 内部一律存「增减百分数」，显示统一过 `toGame()`（后坐力 × −1），读回来过 `fromGame()`。
- 三处必须按「显示口径」排序：`theory()`、`rgRange()`（取 `MIN(g4, g6)`）、区间表翻符号
  （`if (row === RECOIL_ROW && isPos) f = -f;`，只在正面表翻）。
- 紫卡命名取「最大增益」，用单独的 `theoryGain(row)`（内部口径浮动取 1.1 端）。
- 卡面浮层放行后坐力自己的符号，只补正号。

### 1.6 卡面百分号

- `%` 的唯一来源：`rcardHtml()` 里 `if (NON_PCT.indexOf(it.row) < 0) sv += '%';`。
- 穿透(20) / 初始连击(27) / 连击持续时间(28) / 范围(34) 游戏里是绝对值，不加 %（复用 `NON_PCT`）。
- xlsm 洗卡模拟器的数值格单元格格式为 `\+0.00;\-0.00;0.00`（派系行 `"×"0.00`），
  7 张表无一处用百分号格式 —— 网页卡面带 %、xlsm 不带，是两边有意不一致。
- `kfmt()` 保持不带 %（计算器表格、等级换算表显示口径不变）。
- 卡面一行是「数值 + 空格 + 词条名」，`%` 不在行尾。

### 1.7 全站铁规则常量（`window.RULES`，`源码/公共/_rules.js`）

| 常量 | 值 |
|---|---|
| `RECOIL_ROW` | 25 |
| `NEG_ONLY_ROW` | 30（概率不获得连击数） |
| `NON_PCT` | `[20, 27, 28, 34]` |

### 1.8 辣椒定价

| 锁定情况 | 每次洗的单价 |
|---|---|
| 什么都不锁 | 3,500 |
| 只锁融合词条（不管几条） | 3,500 |
| 只要锁了基础词条（不管几条） | 7,000 |
| 融合 + 基础一起锁 | 7,000（基础说了算） |

判据：`rollCost(card)` 看有没有锁住非融合行（`row < FUSE_FROM || row > FUSE_TO` → 7,000）。
定价按「洗」那一瞬的锁定状态算（`var cost = rollCost(card)` 写在 `genStats()` 内）。
总量走 `kuvaFmt()` 千分位，不依赖 `toLocaleString`。

### 1.9 基准值

- 基准值是 ÷ 9000（穿透 / 范围 / 初始连击 / 连击持续时间四条 ÷ 90），不是 ÷ 150；组合系数 0.99 由此而来。
- 类别存盘时默认值 = 近战·天工造武。

### 1.10 基础数值取列（紫卡侧）

紫卡数值的「基准值」只有一张表：`ZKDATA.stats[*].v[]`，五列依次是步枪 0 / 霰弹 1 / 手枪 2 / 曲翼 3 / 近战 4。

| 出口 | 取列方式 |
|---|---|
| 01 区间表 | `baseOf(row, cat)` → `ZKC.catCol(cat)` |
| 02 / 03 / 04 卡面与满值 | `capOf(C, row, sign, tier)` → `CATCOL[C.cat]`（= `ZKC.CAT_COL`） |
| 05 建议器 | `RIVEN_ROUTER.statCap` → `rivenCol()`（`ZKC.dispRec(w).cat` → `catCol`）；认不到表记录才退回战斗槽位 `SLOT_COL[gunClassOf(w)]` |
| 速查表 | `ZKC.CAT_COL[cat]` |

- 类别 → 列的唯一入口是 `ZKC.catCol` / `ZKC.CAT_COL`（由 `names.json` 的 `types[*].col` 生成）：`组合枪 → 2（手枪列）`、`同伴武器 → 0（步枪列）`、`近战·天工造武 → 4`。
- **两个维度不要混**：紫卡数值按上表取列（组合枪主手 / 副手都吃手枪模版，Riven Family 共用一张卡）；配卡 / mod 池按引擎战斗类型（`w.c === 'shotgun'` → 霰弹池，`w.s === 'p'` → 主武器槽）。
- 引擎库 `WEAPON_DB` 没有类目字段，`rivenCol()` 只能按名回查表记录；组合枪在引擎里只记裸名（`Gaze`），表里分 `(Primary)` / `(Secondary)`，`ZKC.dispRec` 末段按 `w.s === 's' ? secondary : primary` 回落，另一条兜底。
- 探针闸门：`_probe_sgx` 的「引擎基础值 ≡ 基础数值表（逐词条 × 逐类型）」必须 `0/0`；「02 满值 与 05 满值 逐武器 × 逐词条同源」必须 `0/N`（当前仅 4 把显赫爪未入表，本来开不出卡）。

### 1.11 显示小数位

| 内容 | 位数 |
|---|---|
| 倾向 | 2 位（`dispText` / `n2`，全站统一 `1.20`） |
| 紫卡词条数值、区间、满值、浮动、边际 | 2 位 |
| 结构系数（正面 / 负面系数） | 最多 4 位且去尾随零（`nz()`：`0.9375` / `0.75`，不写 `0.7500`） |

- 派系词条例外：显示 `×1.45`（2 位），输入框给 4 位（详见 `05_输入框规则汇总.md`）。

3. `Ceti` / `天仓` / `天倉` 已补进关键词清单（清单源自武器倾向表的「②变体关键词清单」页）。
4. 同一把有多个候选时按 EN 优先的 `_CFG` 顺序取（唯一一例：`Dex Furis`）。

### 2.4 倾向快照（倾向版口径的数据来源）

- `ZKDATA.dispSnapshot` 存 637 条历史值，按 `weapons` 下标一一对应。
- 倾向版表格用 `dispOf(i)` 优先读快照、缺失时回退 `w.disp`；637 条共 46 种值（0.50~1.55）。
- 渲染后各星级列的倾向区间单调递增（1星 0.50~0.80 → 5星 1.31~1.55）；错位会使该规律立刻崩掉。
- `data.json` 里带 `dispSnapshot` + `meta.dispositionUnified`，避免重跑 `export.py` 时快照被清空。

### 2.5 合成武器（组合枪 / 天工造武）的倾向

- 倾向表里的 `(Primary)` / `(Secondary)` 是**主手 / 副手**两条，不是「步枪 / 手枪」；两条各带自己的历史倾向（例：孢射 副手 `0.60`、主手 `1.15`）。
- 04 组装台的合成武器，`C.disp` 必须取 `ZKC.disp(C.w)`，**不许写 `DISP_ALL`**；`C.cat` 仍强制 `手枪`（决定紫卡取列），`C.w.c` 保留 `shotgun` / `rifle`（决定 mod 池）。
- 05 组装台拼出来的合成武器没有 `cat`，`statCap` 靠 `ZKC.dispRec` 的裸名回落认到表记录，取列才与 02 / 04 一致。
- 探针：`_probe_dispui` 的 `ASM-DISP`（副手 `0.60` / 主手 `1.15`）。

## 三、识别（截图 OCR）

### 3.1 结构与注入顺序

| 文件 | 职责 |
|---|---|
| `源码/识别/preprocess.js` | 公共预处理层，只认图片不认引擎：紫色边框扫描 → 凸包 + 最小外接矩形旋正 → 贴模板 632×800 → 亮度掩膜 / 对比度自适应 → 去孤立碎块 → 多尺度缩放 |
| `源码/识别/polar_templates.js` + `polar.js` | **极性识别（图标链路，不走文字 OCR）**，见 3.6 |
| `源码/识别/ocr_onnx.js` | ONNX det + rec 本地推理 + 多尺度投票 |
| `源码/识别/ocr.js` | 分区、解析、投票、落对照表（读字后的逻辑） |

- `build.py` 注入顺序：`ONNX 模型常量 → preprocess.js → polar_templates.js → polar.js → ocr_onnx.js → ocr.js`。
  公共层只认图片不认引擎，必须先于识别引擎定义；极性模板须先于 `ocr_onnx.js` 就位
  （`onnxFullRows` 里 fitToTemplate 后立刻调 `PolarOCR.detect`）。
- **只有一条识别路径：本地 ONNX**。`recognize(opts)` 不接受 `engine` 参数，失败即报错，没有联网兜底。
- ONNX 运行时三级兜底（内嵌 → 同目录 `./ort/` → CDN 常量）；离线三件套（运行时模块 / wasm 胶水 /
  wasm 本体）缺一即等于没离线。交付件里 `ORT_CDN` 为空串，第三级走不到。

### 3.2 定标与组合判定

- `settleRankCombo` 把**等级 × 变体 × 组合**一次搜定（必须在 `sanitize` 之前：
  组合判定要用等级反解浮动，定标要用组合算数值，三者互为前提）。
- 排序键统一走 `settleBetter`：bad → pen → absMean → cost → worst；
  变体代价 `SETTLE_W.wVar = 1.5`。
- 组合死规矩：只有 2+0 / 3+0 / 2+1 / 3+1 四种。认出 2 条 → 必定 2+0；
  认出 4 条 → 必定 3+1 且减益永远在卡面最后一行；认出 3 条 → 由 `decideCombo` 分辨 2+1 / 3+0。
- 分辨 3 条靠**数值**而不是符号：2+1 增益 1.2375 / 减益 0.495，3+0 增益 0.75，差 1.65 倍；
  拿候选武器的倾向反解浮动（浮动只在 `[0.9,1.1]`）看哪种组合解释得了这几个数。
- 卡面右上角的数是容量消耗（drain）不是等级：
  `DRAIN2RANK = {6:0,7:1,8:1,9:2,10:2,11:3,12:4,13:4,14:5,15:6,16:6,17:7,18:8}`；
  读不出来退回满级 8。`ocr.js` 与 `app.js` 各有一份，必须逐字一致。
- 模板没对上（`fit.mode = full`）不等于放弃：`inkBlocks` 自判前景色、无框时退回无模型连通域、
  `scanAllRows()` 与位置无关全局扫描、整图版本留在 `__fullCanvas` 两版都扫取并集。
- 紫框点数 < 20 时用 `mode='textbox'`（文字行包围盒裁切）兜底，避免整图硬拉变形。
- 名字分区只把**词条带起点**下移；名字区**只许往上放大**（收窄会切掉两行名的第二行），
  另有「向上补行」逻辑（紧贴块顶、字高 ≥ 块高 0.8 的行补进来，最多 2 轮）。诊断字段
  `window.__zones` / `__zoneSplit` / `__zoneDbg` / `__nameRetry`。
- 底栏段位 / 循环：跳过「也是段位行」的副本再取循环行；英文卡先单独找循环关键词
  （含 `Rerfol` / `Rertol` 这类误读）再退回 `Ranks`。

### 3.3 词条与武器名匹配

- 词条按**数据表行号**匹配（`drow`），不按名字字符串；词条名匹配的唯一出口是
  `ZKC.matchStat` / `ZKC.statCanon`。
- 可洗性矩阵 `stats[i].v` 五槽按 [步枪, 霰弹, 手枪, 曲翼, 近战] 排，`null` = 该类别洗不出这条。
  认不出武器名时用 `catsFromAffixes` 求类别交集，再用 `weaponValueFit` 定置信（容忍一条失配），
  结果标 `inferred=true`。反推顺序：先定词条 → 再算类别 → 再挑武器。
- `rankWeapon` 的 en 列只有 ≥80 才采信；中文没读出来时报「没认出武器名，请手选」，不猜武器。
- `lockIconMisread()`：个位数 + 没读到 % + 该词条必然带 % → 判为锁图标误读，投票整簇 ×0.5 并计入 `res.dropped`。
- `NON_PCT_ROWS = [20,27,28,34,16,17,18,42,43,44]`。
- CONFUSE 池：武器池与词条池分开互不串味；可混淆字替换记 0 代价。
  安全判据：每组内属于本池真值字的至多 1 个（真名互换碰撞检测）。
- 武器名共同字打分按名长归一：`64 + 36×共同字/名长`（封顶 96）。
- 生僻字（蝰痃薙蟥啐嵴牝珽菈）不在 OCR 字典里，只能靠「错读字 → 真值字」单向纠回：
  蝰→奎、痃→玄、薙→稚、蟥→黄、啐→卒、嵴→脊、牝→牡、珽→廷、菈→拉。9 字拼音已在 `PINYIN_MAP`。
- 紫卡名校验：`rivenGenLatin` / `crossCheckName`（`foldLatin` 归一、nearHit 0.75 放行）。
  `latinIsRivenName()` 判「整串能由词根拼出 ≥80% 且命中 ≥4 字符」的拉丁串为紫卡名，不参与武器英文比对。
- `nameLocked`：中文 / 英文名 `score >= 92` 时 `cands = [cur]`，不再做同族扩展。
- 重复行去重三套机制：跨版相似度 ≥78、`byRow` 同表行去重、多票聚类（读数差 <0.15）。
- 后处理（符号还原、派系、去重、组合判定、反推武器）全在 `finalize()`；词条名与类别的
  跨文件调用统一走 `window.__OCR_API` 桥（`ocr.js` 是 IIFE）。

### 3.4 文本输入三类

`parseLabeled` / `parseShorthand` / `parseFreeText`，三类输入最终汇到同一套 `ocrApply` 落槽，判定规则一致。
已支持的输入形态：标签多行 / 单行、口语缩略、数字-词条名配对、模糊次数（`洗了两百多次` → `[200,300]`）、
中文千位 / 万位模糊、交易价格词忽略、带数值原样保留不升满级。
紫卡名反推：国服中文核心词映射（`冷酷`=暴击几率、`重伤`=暴击伤害）、词缀根链式识别
（`霓霆`=电击 / `贯穿`=穿透 / `分裂`=多重）、拉丁词根（`Geli-ata` / `Manti-geliata`）、
浮动系数按词条顺序（第 1 条 1.09 / 第 2 条 1.05 / 第 3 条 1.01）。

### 3.5 已知误读护栏

1. 逗号小数点（`92,7%` → 92.7）；
2. 百分号被读成 `0/0` 或 `O/o`；
3. `+61 0/0`；
4. 词条名首尾的锁字符 `a/o/q/e` 剥离；
5. em dash（U+2014）也当负号；
6. 循环图标被识别成数字 0（`019` → `19`）；
7. 横槽图标被识别成 `18-` / `18一` → Naramon。

### 3.6 极性识别（图标链路，`源码/识别/polar.js`）

- 极性是右上角徽章里的**图标**（Naramon 横条 / Vazarin 倒三角盾 / Madurai V 形），不是文字。
  截图路径在**文字识别之前**单独跑图标识别，结果写 `res.pol`，`ocrApply` 直接填入计算器
  （`K.pol = res.pol || 'madurai'`）。
- 算法：fitToTemplate 产出 632×800 模板图 → 裁固定徽章区（x 72.8~91.7% / y 6.5~15.7%）→
  「18 定线 + 同高」策略隔离右带图标 → 与三张 32×32 标准图标（`window.POLAR_REFS`）做
  **bbox 拉伸 IoU**（模板按候选实际宽高比拉伸后再比，抵消 fitToTemplate 的形变）。恒三选一，不输出「无法判定」。
- 兜底：有图标但三种分不清（最高 IoU < 0.35）→ 按最高分输出 + `polLow=true`，并再试一次右上角紫色自动扫描；
  **徽章区根本没找到图标** → 默认 madurai + `polLow=true`，且**不启动自动扫描**
  （扫描会把游戏 UI 的紫色元素当极性图标）。
- `POLAR_REFS` 缺失或异常 → 返回 null，绝不影响文字识别。

### 3.7 OCR 模型版本

- 当前交付线用 **PP-OCRv6_tiny**（det + rec），模型与字典在 `源码/识别/models/`。
- 构建必须显式带 `OCR_VER=v6 GZ_MODELS=1`：`build.py` 默认仍是 `v3`，
  不带会得到字典行数不同、识别更慢的「假新版」。
- 模型 gzip 压缩后分块 base64 内嵌，页面空闲时才解码，不阻塞首屏。

## 四、WM 拍卖填充

### 4.1 词条按行号取，不按名字

- 网页侧的名字与 WM 下拉原文经常不一样（`对Corpus的伤害` ↔ `对 Corpus 的伤害`；
  `Weakpoint Critical Chance` ↔ `Weak Point Critical Chance`；`Recoil` ↔ `Weapon Recoil`）。
- 一个 ID = 一个概念：`WM_STAT_ID[id] = [国服名, 国际服名, WM中文原文, WM英文原文]`，
  按数据表行号取（`WM_STAT_ROW_ID[row]`），行号唯一。填 WM 只用后两个。
- 词条 ID 表 51 条，四语齐全无空列。

### 4.2 WM 语言与界面语言分离

WM 站点只有一个语言开关，模拟器有国服 / 国际服 / English 三档，两者分开处理：
`window.WM_LANGI()` 返回 WM 站语言，`window.WM_LANGSET(v)` 可单独切，默认跟随界面语言。
WM 英文站 → 词条取 ID 表 `[3]`、武器名走 `WM_WEAPON_CN2EN`；
WM 中文站 → 词条取 `[2]`、武器名直接用 `WM_ITEM_LIST` 原文。

### 4.3 归一化规则（三条，都是「看起来对、实际错」）

1. **英文侧不删字母** —— `Ack & Brunt` / `Tak & Lug` 等七个 `&` 系列武器删字母后会压成同一个键。
   只去空格 / 统一中点 / 转小写。
2. **中文侧不删括号内容** —— WM 里「制胜者 (近战)」/「制胜者」是两个条目。只去空格、全角括号统一半角。
3. **跨语言两份排序列表不按位置配对** —— 英文侧字母序、中文侧拼音序，按位置配对会让「伤害」配到 `Status Duration`。

### 4.4 选中判定

- `nameHit`：形态后缀必须「都有或都没有」——`Vinquibus` ≠ `Vinquibus (Melee)`；裸名包含不判中；
  `MK1-布莱顿` = `布莱顿`（连字符不算形态分隔）。
- `FORM_SUF()` / `stem()`：括号与中点是形态分隔符，连字符不是。`zhNorm()` 拆成 `zhOnly()` + `nameHit()`。
- `wmItemNameAny()` 依次试 `w.cn` / `w.intl` / `wname(w)` / `w.en`，哪个在 WM 下拉里存在就用哪个。
- MK1 变体：国服「试用型-」、国际服「MK1-」都翻到本体名。

### 4.5 标签定位

- WM 中英文站的表单标签都是英文 `Weapon Name`（中文站的 `application-locale-messages` 是中文，
  但表单标签没跟着翻）。候选 `WM_WEAPON_LABELS`：英文 `weapon name` 优先。
- 词条不靠标签定位，走 `statRows()` 按 `attribute-seeker` 类名。

### 4.6 倍率换算

- 派系词条的正反两面统一换算 `1 + v/100`，符号由 `neg` 决定，与模拟器 `toGame()` 同一式子。
- 倍率本身恒为正（0.57 / 1.43），不写进 `value`（否则 0.57 变 −0.57 会掉出倍率框区间）。
- 负面派系文本输出 `×0.57` 而不是 `−50.12`。

### 4.7 词库源文件（`web/源码/填表/`，都是人可维护的 txt）

| 文件 | 内容 |
|---|---|
| `wm-stat-id.txt` | 词条 ID 表 `ID\|行号\|国服\|国际服\|WM中文\|WM英文`，51 条 |
| `wm-items-en.txt` | WM 武器下拉英文原文 |
| `wm-items-id.txt` | 武器中英对照 `WM英文名\|WM中文名` |
| `wm-stat-items-cn.txt` | WM 词条下拉中文原文 |
| `wm-stat-items-en.txt` | WM 词条下拉英文原文 |
| `wm-dict.txt` | 武器别名（Zaw 音译）+ 武器变体命名规则 |

- 编译器唯一：`_wmdict.py`；`_dict.js` 是 `python _wmdict.py --dump` 导出的参考件，不参与构建。
- 构建期校验：词库 JS 语法体检（`node --check`）+ `_chk_dict.js` 逐项核对。

### 4.8 构建期剥注释

- `wm_strip.py` 是严格词法级的 JS 注释剥离器（字符串 / 模板串 / 正则字面量内部原样保留），
  `build.py` 内联 `wmCoreB64` 前先剥注释，并 assert 产物里无残留。
- `wm-fill-core.js` 源码保留全部注释（唯一可编辑真源），剥离只发生在生成出来的脚本上。
- 这里是「压连续空行为 1 行」，与交付件整体去注释（保留空行数）是两件不同的事，别混用。

## 五、构建（`web/`）

### 5.1 入口与占位符

- 组装入口 `build.py`：**占位符替换（28 个，另 `__RIVENIMG__` 在 `js` 上单独一步）**、
  WM 词库构建期现场编译、WM 核心 base64 注入、riven 引擎四件套注入、`window.RULES` 注入、
  落地硬校验、源码体检闸门。
- 替换顺序（`__JS__` 必须最后替：WM 段里有 `__WMCORE_B64__` 之类标识符）：
  `__CSS__` → `__COMMON_JS__` → `__ZKNAMES_JS__` → `__ZKDATA_JS__` → `__RULES_JS__` →
  `__RIVEN_ENGINE__` → `__ZKSTANCE__` → `__ZKMODS__` → `__ZKARCS__` → `__WEAPON_DB__` →
  `__ZKASM__` → `__RIVEN_ROUTER__` → `__CARDSPLIT_JS__` → `__MODPANEL_JS__` → `__ZKC_JS__` →
  `__THEME_JS__` → `__LANGFLOAT_JS__` → `__STATTABLE_JS__` → `__SGX_JS__` → `__WEPTABLE_JS__` →
  `__PRICE_JS__` → `__PRICETABLE_JS__` → `__PRICEDB_JS__` → `__PRICEREF_JS__` →
  `__WMCORE_B64__` → `__OCRJS__` → `__BASEDATA__` → `__JS__`。
  ★ 占位符名字不能和源码里的标识符撞名（源码写 `window.ZKDATA`，占位符就得是 `__ZKDATA_JS__`），
  否则 `replace` 会连源码那处一起替掉。
  ★ `__COMMON_JS__` 必须排在任何业务块之前：全站唯一的 `esc` / `safeParse` / `escNote` / `warn`
  都在 `common.js` 里，后面的块一律转调它。
- 新增源文件要同时登记到 `build.py` 的替换链、未替换 assert 与 `squeeze_src.py` 的 `BUILD_FILES`
  （`BUILD_FILES` 用中文目录名 `源码/框架` 等）。

### 5.2 五个构建约定

1. **产物统一 CRLF**（零裸 LF）。`build.py` 读入走 universal newlines，写出整体转 CRLF，`--lf` 可出 LF 版。
2. **被注入的源文件里不加任何自造头注释** —— `build.py` 是整段拼接，注释会原样进产物。
3. **WM 三块（`_reader.js` / 词库 / `_gen.js`）按产物形态存储** —— 产物里 WM 段嵌在
   `app.js` 的 IIFE 内部，缩进不规则，「顶格存储 + 构建时统一右移」对它不可逆。
4. **交付件去注释的规则固定为「★ 保留 / 其余剥」**（`embed-ort.py --strip`，实现见 `构建/strip_html.py`）。
   `★` 开头的注释是活的约定文档；其余注释剥成空串、**换行原样保留**，所以行号与源码一一对应。
   只做词法级删除（字符串 / 模板串 / 正则字面量内部不碰）。**顺序**：先 `embed-ort` 再 strip。
   ★ 保留 ★ 的副作用：注释里不写外部参照来源（会随注释进产物）。
5. **构建必须可复现**：gzip 的 `mtime` 一律钉成 0（`build.py` 的 `_gz()`），
   否则同一份源码隔两分钟构建会得到不同的字节流，diff 全是噪声。

### 5.3 公共层 `common.js` 与源码体检闸门

**公共层**（`web/源码/公共/common.js`，构建时由 `__COMMON_JS__` 排在 theme 之后）：

| 出口 | 用途 | 为什么非要有 |
|---|---|---|
| `esc` | HTML 转义，`& < > " '` 全转 | 各块各写一份会逐份漂移；漏单引号那份拼进属性值就会截断标签 |
| `attr` / `attrs` | 拼属性用 | 让调用点一眼看出「这里在拼属性」，键名强制白名单 |
| `setText` / `setHTML` | 纯文本 / 已转义 HTML 的两个明确出口 | 减少裸 `innerHTML` |
| `escNote` | note 专用白名单（`span.ok/warn/bad`、`b i em strong br`） | note 要标签，但不能因此整条放行裸 HTML |
| `safeParse` | JSON 解析失败给兜底值 | 快照串经 localStorage 往返，旧档 / 手改 / 截断都会抛 |
| `reEsc` | 正则转义 | 名字叫 esc 却不转 HTML，是最危险的误读 |
| `warn` / `warnDump` | 异常留痕（默认静默、进 200 条环形缓冲） | 空 catch 等于线上零痕迹 |
| `watchInnerHTML` | `?zkdebug=1` 下给 `innerHTML` 打桩 | 开发期发现漏转义，生产零负担 |

- 各业务块顶部一律 `function esc(s){ return ZKHTML.esc(s); }` 转调，**不许再写第二份实现**。
- 排查：`__zkWarnsDump()` 看全部留痕；实时输出加 `?zkdebug=1` 或
  `localStorage.setItem('zkdebug','1')`。
- **源码体检闸门**（`构建/_audit_js.py`，由 `build.py` 每次调用，不达标直接构建失败）：

  | 指标 | 阈值 | 为什么 |
  |---|---|---|
  | 空 `catch (e) {}` | 必须 0 | 吞异常 = 线上零痕迹 |
  | `for...in` 缺 `hasOwnProperty` | 必须 0 | 原型上多一个方法就会被当数据读写 |
  | `innerHTML` 出口数 | 只统计 | 靠 `?zkdebug=1` 打桩逐条告警 |

### 5.4 weapon-db 池化

- 产物里的 `WEAPON_DB` 是池化版：重复字符串在构建期换成负数索引 `-(idx+1)`，运行时还原。
- 只池化出现 ≥2 次的字符串；索引按「首次出现顺序」排，保证幂等。
- 池化前先扫原始数据有没有负数（有则还原时会被误当成索引），`_pool_wdb.py` 直接报错拒绝写出。
- `weapon-db.js` 不是严格 JSON（含 `Infinity`）：先换 `"@@INF@@"` 再 parse，输出时还原。
- 源码 `源码/引擎/weapon-db.js` 保持人可维护的可读版。

- 版块顺序与导航顺序由 `源码/框架/app.js` 的 `FN_SECS` 定义，调序只改那里。
- `#about` 的 `sec-n` 在模板里手写（`fnApplyOrder()` 只给 `FN_SECS` 里的编 01~N），
  新增功能区要手动 +1。
- 导航是 scroll-spy（滚动高亮）不是标签切换；`section{scroll-margin-top:58px}` 配合 sticky，
  跳转时版块标题不会被标签条压住。
- 01 区右下「属性数值速查」（`源码/框架/sgx.js`）跟着当前选中的武器走：`ZKSGW(w)` 是唯一入口
  （01 选武器 / 02 03 04 05 换武器都会调），`follow()` 把类别切到该武器所属类，`selChip()` 在
  `#sgxSel` 写「按 + 武器名 + · 倾向 X」；倾向态下数值按该武器倾向，主态全库统一 1.2 故同类别数值相同，
  文案加「（统一）」说明。手点别的类别则 chip 收起、按默认倾向算。
- 05 洗卡左右建议器（`源码/框架/modpanel.js`）自带一套满值 / 浮动渲染，值来自
  `RR.statCap(ew, 词条键, 正负, tier)` 现算，**不订阅 `zkdispchange` 就不会重算**；
  该模块必须在口径切换时 `renderBasic() + paint()`，否则切完口径只有 02/04 变、05 留在旧值。
  `ew` 是引擎库记录（无 `disp` 字段），倾向仍靠 `ZKC.disp(w)` 按名回查。

### 6.2 卡面宿主

| 宿主 | 槽 | 说明 |
|---|---|---|
| `#c3wrap` | `C[2]` | `#open` 右「继续洗卡」 |
| `#c2` | `C[1]` | `#open` 左「开紫卡」（无锁定列） |
| `#c2wrap` | `C[4]` | `#open` 右「继续洗卡」—— 自己独立的槽 |
| `C[3]` | — | 只剩「记住当前选了哪把武器」 |

按钮 `data-b` 块号约定（`cardHtml(blk)` 的 blk）：`1`=开卡左 / `2`=洗卡右 / `3`=洗卡左 / `4`=洗卡右。

### 6.3 双卡对比

- 两块「洗卡前 / 当前」，左卡取撤销栈顶 `UNDO[UNDO.length-1]`
  （永远等于「按下撤销会变成的样子」），右卡取当前状态 `snap()`。
- 两块各盯各的卡：`.cmpc[data-cmp]`，①=`"2"`、②=`"1,4"`；
  `renderCmp()` 遍历每块，`cmpBlk(host, chg)` 自己算，这次动的卡不在自己 `data-cmp` 里就沿用上次那张。
- 哪个块被改 = `blkChanged(a, b)` 比出来（逐块 `JSON.stringify`，按 `[1,4,2,3]` 取第一个不同）。
- 两颗撤销都跟顶栏共用 `syncHist()` 同步 `disabled`；两张卡必须纯显示（块内没有 `input/select`）。
- 状态 `rerolls` / `kuva` 存在卡上、随快照进撤销栈；开紫卡 / `#open` 换武器清零。

### 6.4 搜索候选行

- 名字一行、标签整体换行：`.cand b{white-space:nowrap;min-width:0;text-overflow:ellipsis}` +
  `.cand{flex-wrap:wrap}` + `.cand b{flex:1 1 auto}` + 「变体标签 + 类别·倾向」包进 `<span class="meta">`。
- 宽容器下名字吸收剩余宽度、`.meta` 被推到最右；窄容器下折行后 `.meta` 落在第二行靠左，
  一个断点都不用写。`.r-wlist button` 同一个病，同样堵上。
- `.cand .cat` 不许自己 `margin-left:auto`（折行后会把 meta 推到行尾）。

### 6.5 手机端

- 卡片流（`@media(max-width:860px)`）：数值列 `flex:0 0 78px`、锁定列 `flex:0 0 72px`、
  显示列 `flex:1 1 0;min-width:76px`；输入框 `font-size:var(--fs-12);min-height:30px`，
  显示列 `--fs-14;font-weight:700;white-space:nowrap`。
- 锁定列不能给 62px（「不锁」+ 下拉箭头 + padding 至少 70px，62px 会被截成「不钅」）。
- 量手机宽度必须用五位数（`164.44` / `160.56`）在 360px 下量，三位数盖不住这个 bug。
- 手机排版不能用 jsdom 验（没有排版引擎），用 `调试/取数/mobile_shot.py`；
  Windows 上 Chrome 无头窗口最小宽 ~500px，脚本把页面塞进定宽 iframe，
  父页加 `--allow-file-access-from-files` 抄结果。

### 6.6 样式约束

- 新样式禁止写死颜色（含 alpha），一律走 semantic 变量（`--pos-text` / `--bg` …）；
  语义层常指向 primitive（`--p-green-300`），判色相要一路解到真值。
- 正面 = 绿、负面 = 红，是一对全局变量（`--pos*` / `--neg*`），改一处全页统一。
- 图标一律 SVG `<use href="#i-…">`，不用 emoji。
- 卡面浮层 `.rcard-txt{left:9%;right:9%;top:46%;bottom:12%}`；卡面 400px 高里
  y≈180–355 才是黑字区（45%~89%）；派系行（倍率类）不翻符号，只有负面槽翻成 `−`。
- 徽章 `.badge-edition` 全部尺寸用 em，跟着 h1 的 `clamp(20px,3vw,28px)` 缩；
  `max(10px,…)` 是给 320~400px 兜底。

## 七、xlsm 侧口径

- **语言位掩码：1=英文(C) / 2=国际服(D) / 4=国服(E)**（`M>=4`=国服、`MOD(M,4)>=2`=国际服）。
