# 05 · 输入框（文本框）规则汇总

> 网页版单文件 `web/产物/20261027紫卡模拟器V8.html`（主版，全库统一倾向 1.2）及其源码 `web/源码/`（按 `公共/数据/引擎/框架/识别/资源/填表` 分层，构建脚本在 `web/构建/`）。
> 每条都标了**代码位置**，改规则时按位置找，别全文搜名字。
> 口径总原则：**输入框里填的是"游戏里看到的那个数"，内部一律存"增减的百分数"**（见 §4）。

---

## 1. 通用规则（所有输入框都适用）

| 规则 | 说明 | 位置 |
|---|---|---|
| 归一化 `squash()` | 去掉所有空白（含 `空格 / \u00A0 / \u3000`）再 `toLowerCase()`；**只做去空白+小写，不做拼音、不做分词** | `app.js:43` |
| 转义 `esc()` | 所有来自数据的文本进 `innerHTML` 前必须先 `esc()`（爬来的名字里带过 `&amp;` / `<` / 引号）；唯一例外是 `note`（本身含 `<span class="ok">`） | `app.js:50` |
| 事件：`change` | 数值类输入框**统一走 `change`**（失焦/回车才提交），不实时重算 | `app.js:1871`、④ 区 `app.js:3264` |
| 事件：`input` | **只有三个搜索框**走 `input`（实时出候选）：`#q` / `#q1` / `#rgQ` | `app.js:1972`、`app.js:3268` |
| Esc | 在 `#q / #q1 / #rgQ` 里按 Esc = 清空候选列表（`CAND[]=[]`、`HOT[]=-1`、④ 区还清 `RG.q/RG.hot`） | `app.js:1984` |
| **Ctrl+Z 在文本框内交还浏览器** | `inText`（`INPUT[type=text|search]` 或 `TEXTAREA`）为真时不拦 Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y —— 想撤销的是刚敲进去的字符，不是页面历史 | `app.js:1980` |
| 数值兜底 | 解析不出数 → `parseFloat()` 得 NaN，各框有各自的兜底（见 §3 表） | 见下表 |
| 图片不走文本框 | `Ctrl+V` 粘贴 / 拖入 / `#ocrFile` 选图 是**另一条输入通路**（OCR 识图），见 §5.4 | `app.js:2676` |

## 2. 三个搜索框（武器名）

| 框 | 区域 | 候选盒 | 选中后 |
|---|---|---|---|
| `#q` | ② 数值计算器「搜索武器」 | `#cands` | `pickCalc(idx)` |
| `#q1` | ① 开紫卡 / 选武器 | `#cands1` | `pick1(idx)`（填 `C[2]`、`ACTIVE_BLK=2`、洗一次） |
| `#rgQ` | ④ 倾向数值区间表 | `#rgCands` | `rgSetWeapon(idx)` |

**匹配算法**（`findWeapon`，`app.js:174`）：

1. 输入先 `squash()`（去空白 + 转小写）。
2. 索引 `WIDX` 的键 = 每把武器的 **国服名 / 国际服名 / 英文名** 三条（`app.js:163`），也 squash 过。
3. 匹配方式 = **子串包含**（`key.indexOf(q) >= 0`），不是前缀、不是拼音、不是模糊相似度。
   - 例：输 `torid` 命中 Torid；输 `里德` 命中"托里德"；输 `布拉玛` 命中"赤毒布拉玛"。
4. 同一把武器的三条名字都命中时**去重**（`seen`），只出一次。
5. 结果上限 **40 条**（`app.js:174` 内 `break`）；但 **UI 只显示前 10 条**（`drawCands` 里 `.slice(0, 10)`，`app.js:1655`）。
6. 空输入 → 立刻清空候选，不显示"没匹配到"。
7. 有输入但 0 命中 → 候选盒显示「没匹配到武器」。
8. **变体也能搜到**（要能查它的倾向和数值），但会打标 `变体 · <本体名>`；变体开不出紫卡，紫卡按本体命名。

**键盘**（`app.js:1999` / ④ 区 `app.js:3271`）：

| 键 | 行为 |
|---|---|
| `↑ / ↓` | 在候选里循环移动（`+n) % n` 环形），`#q`/`#q1` 走 `moveHot`，`#rgQ` 直接改 `RG.hot` |
| `Enter` | 选中当前高亮项（没高亮默认第 0 条），`preventDefault()` 不提交表单 |
| `Esc` | 关候选（见 §1） |

**交互副作用**：选完武器后 `K.manual` 会**被清空**（倾向跟武器走，不留手填值，`app.js:1694`/`2517`）；同时 `autoCmpForVariant(w)` 自动填「对比变体倾向」。

## 3. 计算器 / 卡面的数值输入框

| 控件 | 元素 | 解析规则 | 夹取 / 兜底 | 位置 |
|---|---|---|---|---|
| 词条位数值 | `<input type=number step=0.01 data-a="kval" data-i=i>` | `fromGame(parseFloat(v), K.rows[i])` | 解析不出 → **原样存字符串**（`K.vals[i] = t.value`） | `app.js:1963` |
| 卡面词条数值 | `<input type=number step=0.01 data-a="val" data-b=blk data-i=i>` | `fromGame(parseFloat(v), s.row)` | 解析不出 → `s.val = 0` | `app.js:1917` |
| 手填倾向 | `#manual` | `K.manual = t.value`（**字符串原样**）；非空且 `isFinite(parseFloat)` 才生效 | 留空 = 自动用武器的 `disp` | `app.js:1875`、`572` |
| 当前等级 | `#rank` | `+t.value` | `max(0, min(P.maxRank=8, v \|\| 0))` | `app.js:1876` |
| 段位 | `#mr` | `+t.value` | `max(8, min(16, v \|\| 8))` | `app.js:1894` |
| 对比变体倾向 | `#cmp` | `parseFloat(t.value)` | `\|\| 0`（NaN → 0） | `app.js:1893` |
| 循环次数 | `#cyc` | `+t.value` | `max(0, floor(v) \|\| 0)` | `app.js:1895` |
| 组合类型 | `#combo`（下拉） | `+t.value` | 索引，无夹取 | `app.js:1874` |

**联动规则（改框会带动别处）**：

- **改「当前等级」** → 四个词条位的"当前值"按 `(1+新等级)/(1+旧等级)` **等比例缩放**（紫卡数值随等级线性，改回原等级即还原）。满级（↑）走同一套比例（`app.js:2038`）。
- **改词条位（无→有）** → 自动填「理论最小」`theory(row,'min')`；**有→无** → 清空数值。
- **增删词条导致组合数变化** → 正负词条计数重算 `comboIdxOf(pn,nn)`，并把**其余**词条位按新旧组合系数比例缩放（`app.js:1936`）。
- **锁定状态下不许删词条**：有词条已锁定时，把已填槽选成空白会被拒绝并提示「有词条已锁定，组合类型冻结…」，输入框回滚原值（`app.js:1901`）。
- **融合材料下拉（`#fus`）**：选了一个后，另一个下拉里配不出的选项自动让开（避免选不出可融组合）（`app.js:1928`）。

## 4. 数值口径（填进去的数和看到的数）

内部一律存「**增减的百分数**」（正面槽正、负面槽负，和其余 50 条一致），界面显示的是游戏口径：

```js
toGame(v, row)   // 内部 → 游戏：派系 1 + v/100；其余 v * dirOf(row)     app.js:83
fromGame(v, row) // 游戏 → 内部：派系 (v-1)*100；其余 v * dirOf(row)     app.js:87
dirOf(row)       // 后坐力(row 25) = -1，其余 = 1                       app.js:37
```

| 情形 | 内部值 | 界面 / 输入框 | 备注 |
|---|---|---|---|
| 派系行（row 16/17/18/42/43/44） | `+45` | `×1.45` | 输入 `1.45`；**派系输入框给 4 位小数**（倍率 2 位 = 百分数只到 0.5，来回会磨掉数值） |
| 后坐力（row 25）正面 | `+90` | `−90%` | 方向相反；正面槽显示负值 |
| 后坐力（row 25）负面 | `-80` | `+80%` | 负面槽显示正值 |
| 绝对值词条 `NON_PCT = [20,27,28,34]`（穿透 / 初始连击 / 连击持续时间 / 攻击范围） | 数值本身 | 不带 `%` | 连击持续时间 8.1 是**秒**，不是 81% |
| 其余 | 增减百分数 | `+12.34%` / `-5.60%` | 2 位小数 |

- 显示格式化 `fmt()`（`app.js:192`）：派系 `×1.45`（2 位小数），其余 `±x.xx%`（`NON_PCT` 不加 `%`）。
- 输入框取值 `inpNum()`（`app.js:203`）：派系 4 位小数、其余 2 位，**一律先过 `toGame()`**。
- 浮动系数：`lo 0.9 / mid 1.0 / hi 1.1`，默认倾向 `defaultDisp 0.5`，变体阈值 `variantTh 0.11`，满级 `maxRank 8`（`window.RULES` 等配置常量，构建期由 `数据/` 导出、内联进 `window.ZKDATA`）。
- OCR/文字识别侧的**百分数 sanity**：`>300` 且 `/10 <= 300` 就除以 10（`1413% → 141.3%`）—— 若游戏里真有 >300% 的合法词条会被误杀，要改得连这条一起改。

## 5. 文字生成框 `#ocrText`（口语直接生成卡面）

**入口**：点「生成」按钮 `doTextGen()`（`app.js:2259`），或**在框里按 Enter**；「清除」按钮清空并 `focus()`。
**空输入** → 提示「先输入文字，例如：双爆多负触发的托里德」。
**认不出来** → 提示换写法。生成后**不跳转页面**（只有"识别并填入计算器"才滚到搜索武器）。

支持**三类输入**：

### 5.1 口语缩略词（`ocr.js:1870` `SHORTHAND`）

按**长度降序**匹配（`sort(b.k.length - a.k.length)`），长词优先（"负触发" 先于 "触"）。
默认：**3 正 1 负口径、等级满级 8、浮动取最大 1.1**；说到的词条默认带负面（与紫卡名反推一致）。

| 缩略词 | 词条行 | 缩略词 | 词条行 | 缩略词 | 词条行 |
|---|---|---|---|---|---|
| 双爆 | 4 暴击几率 + 5 暴击伤害 | 负触发 | 6（负） | 爆伤 / 暴伤 | 5 |
| 暴击 | 4 | 负触率 | 6（负） | 负多重 | 19（负） |
| 负暴击 | 4（负） | i歧视 | 18 | g歧视 | 17 |
| c歧视 | 16 | o歧视 | 42 | 触时 | 7 |
| 触率 | 6 | 触发 | 6 | 多重 | 19 |
| 初始 | 27 | 弹匣 | 21 | 弹药 | 22 |
| 投射 | 24 | 装填 | 23 | 后坐 | 25（flip） |
| 重效 | 31 | 切割 | 14 | 病毒 | 38 |
| 伤害 / damage | 2 | 范围 | 34 | 攻速 | 8 |
| 负爆 | 5（负） | 负多 | 19（负） | 负触 | 6（负） |
| 基 | 2 | 暴 | 4 | 爆 | 5 |
| 多 | 19 | 触 | 6 | 毒 | 10 |

**负号的判定**：缩略词**前面**一个字符是 `-` `−` `–` 或 `负` → 这条算负面（`ocr.js:2107`）。

### 5.2 数值 + 词条名（自由文本）

例：`泰瑟步枪 79.7多重射击 82.1病毒伤害`
- 武器名按 `WEAPONS.cn` 锚定，可在句首或句尾。
- 数值正则吃 `数字[.,]*` 加可选 `%`；**数值 sanity** 同上（>300 且 /10≤300 则 /10）。
- 词根表与 OCR **同一份**（`AFFIX_TABLE`），带形近字容错（`CONFUSE`：匣↔甲↔便、自↔目、天↔大、穹↔弯、系↔素、舍↔害、药↔约、虐↔速、于↔击、寒↔暴、座↔坐…）。

### 5.3 带标签的"上架信息"（复制粘贴的整段）

例：`武器名称：夜语者77  正面词条：穿刺伤害 +89.05%  负面词条：弹药最大值 −50.78%  精通段位：8  Mod等级：8  循环次数：10`
（`ocr.js:1937` `labeledAffix` / `ocr.js:1978` `extractMeta`）

- **按标签词切段，不依赖换行**（单行空格分隔也认）。
- 命中词条时取**最长**匹配名（`bestLen`），再往后吃符号+数值。
- 派系行：符号被 `× x X *` 捕获 → 直接当倍率；**没有乘号但给了 `+0.5`** → 归一成 `×1.5`（`sign` 强制 `×`）。
- 符号识别：`+ - − – — × x X *`。

**元数据提取**（`extractMeta`，`ocr.js:1978`）——说到了就解析并从文本里移除，避免干扰武器/词条匹配：

| 提取 | 写法 |
|---|---|
| 段位 `mr` | `精通段位：15` / `段位15` / `Mr.9` |
| 等级 `rank` | `Mod等级：1` / `等级8` / `Ranks:8` |
| 循环次数 `rolls` | `循环次数：1111` / `洗卡次数` / `洗了200次` / `500洗` / `循环20` / `Re-rolls:47` / `O34` / `019`（OCR 把循环图标认成 0，去前导 0 → 19） |
| 零洗 | `零洗 / 没洗过 / 没洗 / 未洗过` → `rolls = 0` |
| 模糊次数 | `洗了两百多次` → 200~300 随机；`200多` 同理。**仅在没拿到精确值时启用**，不覆盖 `洗了200次` |

**没说到时的默认值**：段位 **8** / 等级 **8（满级）** / 循环 **10**（`ocrApply` 兜底）。

### 5.4 相邻的另一条输入通路（不是文本框，但同源）

`Ctrl+V` 粘贴图片 / 拖入 / `#ocrFile` 选图 → 走 OCR 识图，结果同样进 `ocrApply`。规则见 `04_踩坑总表.md` 七、OCR 识别分区。

## 7. 改这些规则时的注意事项

1. **改口径要改两处**：显示侧 `fmt()/inpNum()/toGame()`，解析侧 `fromGame()` 与 `ocr.js` 的 `parseAffixes`（派系 `+0.5 → ×1.5` 的归一也在这里）。
2. **改等级默认值**要同时看 `K.rank`（运行时）与 `P.maxRank`（数据，`=8`）；`DRAIN2RANK` 反查等级，只作对照表。
3. **搜索匹配只有"子串"一档**，加拼音/别名要改 `WIDX` 的建索引处（`app.js:163`）与 `findWeapon` 上限。
4. **别在文本框里拦 Ctrl+Z**（`app.js:1980` `inText` 判定）。
5. 改完按项目规矩跑：`python 构建/build.py` → `python 构建/embed-ort.py --strip` → 无头 Chrome 量 `getBoundingClientRect` / 抓 DOM 断言。
