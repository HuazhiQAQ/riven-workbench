Warframe 紫卡模拟器 V10

面向《Warframe（星际战甲）》紫卡 / 裂罅 Mod 的离线单文件工具：双击即开、断网可用，OCR 与收益引擎全部内嵌。

直接打开成品无需安装 · 无需联网
主版 · 15 MB 识别流程原理讲解 · 3.0 MB

都是自包含单文件（JS / CSS / OCR 模型 / ONNX 运行时全部内联），下载后双击即可用。 也可以在 GitHub Pages 上直接点开 —— 首次加载较慢（十几 MB），之后走浏览器缓存。

怎么做的

  • 单文件离线：构建时把 源码/ 拼成一份 HTML，JS / CSS / OCR 模型 / ONNX 运行时全部内联，识别过程不发任何网络请求。
  • 名字只有一张表：武器 / 词条 / 类型 / 变体词 / 派系 / 别名全部收进 源码/数据/names.json，代码里不再各写一份；构建时逐字段比对，表和数据不一致直接构建失败。
  • 词条名是一个键，不是一段文字：「暴击几率」只写在命名表里，引擎 / 面板 / OCR / 价表都只写键 cc（ZN('cc') / SE('cc') / ZKC.statMap('short')）；「暴击率」「Crit Chance」「CC」以及市场挂单里的「弹夹容量」「终结伤害」都登记成同一个键的别名。
  • 任何写法都落到同一样东西：武器名 ZKC.matchWeapons、词条名 ZKC.matchStat 各自一套归一化——全角半角、大小写、连字符、damage vs./to/for corpus 与「对科普斯的伤害」等价；只写本体名自动落到本体。
  • 双重倾向口径：一份产物同时带「全库统一 1.2」与「各武器历史倾向」两态，目录底「倾向口径」页内切换，计算与区间表跟着重算。
  • 行情比价按服取池：国际服与国服各一个在售挂单池，估哪个服就在哪个服的挂单里比；同一套同款匹配 + 相似度加权，负词条按严重度四档折价，国服价格截到 300 上限。
  • 行情库只存键：组合榜 / 单词条榜存 slug，显示名从命名表取；样本去头尾 25% 极值、数值取整。

七个功能分区

分区用途
01 倾向数值区间表每把武器的倾向值与各词条数值区间
02 分析识别计算器粘紫卡截图 → 本地 OCR 识别武器 / 等级 / 四条词条与数值 → 自动填入计算器
03 开卡洗卡融合模拟随机开卡、继续洗、融合；统计次数与辣椒（Kuva）消耗，双卡对比
04 紫卡收益计算器选武器 → 配卡 → 填词条，给出相对「不带这张卡」的收益与每条边际
05 洗卡左右建议器左右两张候选卡各识别一次，同一套引擎现场算，判断留哪张
06 紫卡价值表成交价快照：中位价、均价、未洗 / 已洗、最高单笔、流动性、近 8 周变动；另含单词条热度榜与词条组合价格排名，双服切换
07 口径与词汇数值怎么算、哪些词条不会出现、名词含义

另外：三语言界面（国服 / 国际服 / English）、暗亮双主题、移动端适配。

自己构建

需要 Python 3 与 Node.js 22（仅构建期校验用）：

cd web

# 0) 清注释（新增源文件要先登记到 构建/squeeze_src.py 的 BUILD_FILES）
python 构建/squeeze_src.py --apply

# 1) 组装源码 → 中间产物（第 1 步的输出还没嵌 OCR 运行时，必须接第 2 步）
OCR_VER=v6 GZ_MODELS=1 python 构建/build.py 产物/20261031紫卡模拟器V10.html

# 2) 内嵌 OCR 模型 + 去注释 → 最终交付件
python 构建/embed-ort.py --src 产物/20261031紫卡模拟器V10.html \
                          --out 产物/20261031紫卡模拟器V10.html --strip

两步即可：第 1 步产出的是未嵌 OCR 运行时的中间态，第 2 步才内嵌运行时并去注释。

数据口径
