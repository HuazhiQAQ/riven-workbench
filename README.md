# Warframe 紫卡（裂罅 Mod）模拟器

> 面向《Warframe（星际战甲）》**紫卡 / 裂罅 Mod（Riven Mod）** 的离线工具集：网页版为单文件离线应用，配套 Excel（xlsm + Python）数据维护工具可更新武器倾向表与紫卡命名。

---

## 这是什么

- **网页版（`web/`）**：单 HTML 文件、双击即开、离线可用。覆盖倾向区间表、紫卡计算器、随机开卡 / 洗卡 / 融合模拟、截图 OCR 识别、紫卡收益计算器、洗卡左右建议器、紫卡价值表。
- **Excel 工具（`tools/`）**：带宏的 xlsm + Python 脚本，用于维护武器倾向表、紫卡命名、洗卡模拟与校验，与网页版代码完全独立。

---

## 成品文件

| 文件 | 说明 |
|------|------|
| `web/产物/20261031紫卡模拟器V10.html` | **主版**：双服行情参考 + 页内「倾向口径」切换，约 15 MB |
| `web/dist/riven-workbench-web.html` | **英文名分发版**：同一份构建，英文文件名便于分享，约 15 MB |
| `web/产物/识别流程原理讲解_鳄神案例.html` | OCR 识别流程原理讲解页（18 步，图文自包含） |

三份都是自包含单文件（JS / CSS / OCR 模型 / ONNX 运行时全部内联），**断网可用**，不需要任何服务器。

仓库根目录另有一份 [`index.html`](index.html)：开启 GitHub Pages 后它就是项目首页；本地双击打开也一样能看，不加载任何外部资源。

## 网页版功能

| 分区 | 用途 |
|------|------|
| **倾向数值区间表** | 每把武器的紫卡倾向值与各词条数值区间，按武器类型浏览。 |
| **分析识别计算器** | 粘贴紫卡截图 → 本地识别武器名、等级、四条词条与数值并自动填入计算器；检验对中差值、评级、等级换算。 |
| **开卡洗卡融合模拟器** | 随机开紫卡、自选武器继续洗卡、融合；统计洗卡次数与辣椒（Kuva）总消耗，双卡对比。 |
| **紫卡收益计算器** | 选武器 → 配卡模板 → 填紫卡词条，给出相对「不带这张卡」的 DPS 收益、每条边际与社区分档。 |
| **洗卡左右建议器** | 左右两张候选卡各截一张图分别识别，用同一套收益引擎现场计算，辅助判断保留哪一张。 |
| **紫卡价值表** | 每把武器紫卡的成交价快照：中位价、均价、未洗 / 已洗价格、最高单笔、流动性与近 8 周变动；只列开得出紫卡的武器。另含单词条热度与词条组合价格排名。 |
| **口径与词汇** | 数值怎么算、哪些词条不会出现、名词含义。 |

其它特性：三语言界面（国服 / 国际服 / English）、暗 / 亮双主题、完全离线（OCR 引擎与模型内嵌）、移动端适配。

实现原理、构建与回归用法见 [`web/README.md`](web/README.md)。

## 命名表（名字的唯一来源）

所有名字只有一处可改：**`web/源码/数据/names.json`**。代码里不再各自维护一份名字清单。

| 表内字段 | 内容 | 谁在用 |
|---------|------|--------|
| `types` / `typeAlias` | 武器类型（步枪 / 霰弹 / 曲翼…）的中英叫法、倾向表列序、价表类型键 | `ZKC.typeName` / `ZKC.typeAlias`、`RULES.CAT_COL`、价表 |
| `variants` | 变体词（圣装 / 赤毒 / 信条 / 终幕 / 棱晶 / 异变…） | 武器名归一化（`ZKC.coreOf`）、OCR 变体剥离 |
| `factions` | 派系叫法（科普斯 = Corpus，克隆尼 = Grineer…） | 词条名归一化（`ZKC.statCanon`） |
| `alias` | 别名与错写（冰淞→冰凇、山智段→心智之殁） | 搜索、OCR 回填 |
| `stats` | 51 条词条：行号 / 国服 / 国际服 / 英文 / WM 中文 / WM 英文 | `ZKC.matchStat`、WM 填表脚本 |
| `statKeys` | 90 个词条键（`cc` / `cd` / `ms` …）：中文名 / 简称 / 英文 / 别称 / 对应行号 | 引擎表、面板表、OCR 缩写表、`ZKC.statKeyOf` |
| `weapons` | 637 把武器：英文 / 国服 / 国际服 / 本体三语 / 类型 / 形态 / WM 名 | 名称投影、WM 填表脚本 |
| `wm` | WM 下拉原文（武器清单、中英对照、Zaw 音译别名、变体命名规则） | WM 填表脚本编译（`_wmdict.py`） |

维护方式：

```bash
python 构建/gen_names.py            # 体检：表与 zkdata.js 逐字段比对，不一致就报错
python 构建/gen_names.py --build    # 增量：把 zkdata 里新增的武器/词条补进表
python 构建/gen_names.py --apply    # 反向：用表里的名字覆盖 zkdata.js（改译名走这条）
```

`build.py` 每次构建都会做同一份比对，**表和数据对不上就直接构建失败**；产物里只内联「代码要用的那部分」（类型 / 变体 / 派系 / 别名），武器与词条的名字本来就在 `ZKDATA` 里，不重复塞第二份。

名字匹配（任何写法都落到同一样东西）：

- 武器：`ZKC.matchWeapons` —— `赤毒·食人女魔` / `赤毒食人女魔` / `赤毒 食人女魔` / `kuva-ogris` 等价；只写本体名落到本体。
- 词条：`ZKC.matchStat` —— `damage vs. corpus` / `damage to corpus` / `damage for corpus` / `对科普斯的伤害` / `对corpus伤害` 全部落到同一行（对 Corpus 的伤害）。

### 词条名是一个键，不是一段文字

「暴击几率」这四个字在代码里只出现在命名表里。引擎、面板、OCR、价表都不写名字，只写键：

```js
S({ k: 'cc', n: ZN('cc'), … })      // 结果面板：显示名查表
{ k: 'cc', n: SE('cc'), … }         // 收益引擎：显示名查表
var MKEY = ZKC.statMap('short');    // 面板简称表：整体由表生成
```

于是「暴击几率 = 暴击率 = Crit Chance = CC」都只是同一个键 `cc` 的叫法。价表里那些挂单原文（`弹夹容量` / `终结伤害` / `状态触发几率`…）也不是第二套名字，而是 `statKeys` 里的 `alias`——`ZKC.statKeyOf` 照样认得。

行情库 `zkpricedb.js` 同理：组合榜 / 单词条榜里不存中文名，只存 slug（`ks` / `gk` / `k`），自己的 `stats` 只留 `slug → 词条行号`，显示名一律从 `names.json` 取。价库同时做了瘦身（封顶价丢弃 + 去头尾 25% 样本 + 数值取整），由 `构建/pricedb_slim.py` 重排；脚本不幂等，重跑前先从 `备份/zkpricedb.瘦身前.js` 恢复。组合榜另有一道合法性闸门 `构建/pricedb_fixcombos.py`：紫卡最多 3 正 1 负，正词条超过 3 条的组会被整组删除并按类内中位价重排。

## 快速开始

### 网页版（零安装）

直接用浏览器打开：

```
web/产物/20261031紫卡模拟器V10.html
```

这是一份自包含单文件网页（JS / CSS / OCR 模型全部内联），断网也能用。另有 `web/dist/riven-workbench-web.html`（英文名分发版，同一构建）与 `web/产物/识别流程原理讲解_鳄神案例.html`（识别流程原理讲解）。倾向口径（全库统一 1.2 / 各武器历史倾向）为**页内切换**，不单独出文件。

### 网页版构建（更新数据后重建单文件 HTML）

需要 **Python 3** 与 **Node.js 22**（仅用于构建期校验）。

```bash
cd web

# 0) 清注释（源码自带；新增源文件要先登记到 构建/squeeze_src.py 的 BUILD_FILES）
python 构建/squeeze_src.py --apply

# 1) 组装源码 → 中间产物（OCR 模型用 v6，并 gzip 压缩以减小体积）
OCR_VER=v6 GZ_MODELS=1 python 构建/build.py 产物/20261031紫卡模拟器V10.html

# 2) 内嵌 OCR 运行时并去掉注释 → 最终交付件
python 构建/embed-ort.py --src 产物/20261031紫卡模拟器V10.html \
                          --out 产物/20261031紫卡模拟器V10.html --strip
```

> 第 1 步输出的是**未嵌 OCR 运行时的中间态**，并会覆盖同名产物，必须接第 2 步。
>
> `build.py` 不带路径参数时默认输出到 `web/dist/riven-workbench-web.html`；要更新正式交付件就显式传 `产物/20261031紫卡模拟器V10.html`。
>
> `embed-ort.py` 内嵌的 ONNX 运行时优先读取本地的 `运行时/`；该目录已从仓库省略（约 14 MB 的 wasm 缓存），重建时加 `--force-download` 即可从 CDN 拉取（需联网）。交付的 `产物/*.html` 本身已内嵌 ONNX，断网可用。
>
> 数据源（`源码/数据/zkdata.js` 等）通常无需改动；仅在武器库或价值表更新时才需要重跑数据导出脚本。

### Tools excel 表（Excel 数据维护工具）

`tools/` 内含带宏的 xlsm。**首次打开需启用宏**（WPS / Excel 会提示）。`紫卡工具箱.py` 与 `融合数值验证.py` 为配套 Python 脚本（离线读写 xlsm）。

当 xlsm 数据有变动、需要重新导出给网页版时：

```bash
cd web/构建
python export.py        # xlsm 离线拆 zip -> 数据文件
python gen-basedata.py  # 需设 ZK_WEAPON_SRC / ZK_RIVEN_SRC 环境变量
```

> Excel 侧的维护流程（改 VBA / 改公式 / 验收 / 踩坑）与网页版完全独立；完整细节见 `01_整体思路与方法论.md` 与 `04_踩坑总表.md` 的 Excel / VBA 分区。

## 数据口径

- 武器 **637 把**（本体 396 / 变体·有本体 218 / 变体·无本体 23）；开卡池 = 本体 + 变体·无本体 = **419 把**（变体·有本体开不出卡，不进开卡池）。
- 词条 **51 条**（`statKeys` 90 个键）；融合配方 **23 条**。
- 倾向默认全库统一按 **1.2** 计算，页内可切到按每把武器历史倾向计算。
- 行情库：国际服 27,942 条在售挂单（420 把武器）、国服 2,349 条（289 把）。
- 详细口径与所有坑点见 `docs/CHANGELOG.md`、`docs/04_踩坑总表.md` 与 `docs/README.md`。

## 回归（可选）

`web/调试/` 下是一组无头 Chrome（CDP）探针，改完代码后用来验证七个分区没被改坏：

```bash
cd web/调试
node run_all.cjs            # 核心集合，自动取 产物/ 下最新成品
node run_all.cjs --ext      # 核心 + 各功能专项
```
